# Мастер шины RS-485 на ESP32 (`esp32_master`)

Прошивка модуля опроса и оркестрации самокалибровки считывающих головок STM32F722RE по выделенной полудуплексной шине RS-485 (ESP-IDF v5.x). Полная спецификация протокола и регистров приведена в [`../docs/modbus_rtu.md`](../docs/modbus_rtu.md).

## 1. Аппаратное подключение и распределение ядер

| Узел | Параметры |
|---|---|
| `UART2` (RS-485) | `GPIO17 = TX`, `GPIO16 = RX`, `GPIO4 = RTS` (`DE` + `/RE`), `UART_MODE_RS485_HALF_DUPLEX`, `230400 8E1` |
| `UART0` (ПК / консоль) | `921600 8N1`, источник тактирования принудительно переведён на `UART_SCLK_DEFAULT` (`APB = 80 МГц`, `922190` бод, `+0.064%`) |
| Core 0 (`PRO_CPU`) | Задача `encoder_bus` (приоритет `configMAX_PRIORITIES - 2`, в ESP-IDF v5.x это `23` из `0..24`) и аппаратный таймер `esp_timer` (`ESP_TIMER_ISR`, `100.000 Гц`) |
| Core 1 (`APP_CPU`) | Задача выдачи `pc_link` (приоритет `4`, `RINGBUF_TYPE_NOSPLIT`, `64 КБ`) и интерактивная консоль `esp_console` |

## 2. Сборка и прошивка

```bash
cd esp32_master
idf.py set-target esp32
idf.py build
idf.py -p <PORT> flash monitor
```

## 3. Команды консоли (`encoder>`)

После включения мастер находится в `IDLE` и не обращается к шине RS-485 до ввода команды оператором.

| Команда | Описание |
|---|---|
| `scan` | Поочерёдный опрос адресов `1..247` (`FC04`, регистры `0..1`; головкой считается любой адрес, давший корректный ответ; только чтение, длительность `~2.1 с`). Список найденных адресов хранится в ОЗУ до следующего `scan` |
| `poll [id[,id...]] [period_us]` | Запуск синхронного опроса (`SNAP` + чтение `11` регистров `0..10` на каждую головку). Без списка адресов берутся головки из последнего завершённого `scan`; период указывается только после списка адресов. Период по умолчанию `10 000 мкс` (`100 Гц`) для `1..3` головок и `11 000 мкс` для `4`; явный `period_us` допустим в пределах `2000..1000000` и не может быть меньше бюджета шины `700 + 2350 * N` мкс |
| `calib [id[,id...]]` | Запуск 4-этапной самокалибровки указанных головок (без аргумента — найденных последним `scan`); перед каждым этапом проверяется сигнатура `0xCA01` в `LIVE`-регистрах `0x0100..0x0102`, опрос `LIVE` в ходе этапа — `20 Гц` (`50 мс`) |
| `next` | Подтверждение оператора перед началом каждого этапа калибровки и перед переходом к следующей головке |
| `stop` | Остановка `scan`, `poll` или `calib` (в режиме калибровки отправляет `0x0010 STOP` на текущую головку и проверяет `state == 0x00`); после `poll` печатается отчёт `POLL_END` / `TIMING` / `POLL_REPORT_DONE` |

## 4. Последовательность самокалибровки (`calib`)

Для каждой головки в `esp32_master/main/workflow.c` строго фиксирован порядок этапов:
1. `0x0014` — выравнивание чувствительности фотодиодов `buf_k[6..126]` (`0x70 -> 0x80`), равномерное вращение в любую сторону (`10..40 об/мин`).
2. `0x0013` — поиск оптического центра `offset` (`0x50 -> 0x60`), равномерное вращение в любую сторону (`10..40 об/мин`).
3. `0x0011` — калибровка таблицы секторов `ang_tab` проход 1 (`0x10 -> 0x20`), равномерное вращение в любом выбранном направлении (`5..20 об/мин`; направление запоминается головкой, подсказка консоли предлагает вращение по возрастанию угла).
4. `0x0012` — калибровка таблицы секторов `ang_tab` проход 2 (`0x30 -> 0x40`), вращение в **противоположную** проходу 1 сторону (`5..20 об/мин`), сохранение в EEPROM и завершающий `0x0010` (`-> 0x00`).

## 5. Формат выходного потока `DATA`

В режиме `poll` каждая итерация `seq` выдаёт в `UART0` одну строку:

```text
DATA seq=<u16> t_us=<u64> snap_us=<u32> poll_us=<u32> error=<mask> id=<id1> ang=<deg|nan> raw_ang=<deg|nan> age_us=<i32> read_us=<u32> gap_us=<u32> ...
```

* `ang` — угол головки в градусах (`6` знаков после запятой), приведённый к общему моменту `t_us` завершения передачи `SNAP`.
* `raw_ang` — исходный угол кадра линейки на момент середины его оптической экспозиции `t_us - age_us`.
* `age_us` — знаковый возраст кадра линейки относительно приёма `SNAP` в микросекундах (`DWT->CYCCNT` головки).
* `error` — битовая маска ошибок цикла по типам, общая для всех головок: `1` — `SNAP` не отправлен, `2` — нет ответа или сбой `CRC` при чтении, `4` — невалидный снимок (`0` — все головки ответили достоверным кадром). Угол отказавшей головки выдаётся как `nan`.
