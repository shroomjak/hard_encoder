# Modbus RTU: головки STM32F722 и ведущий контроллер ESP32

Здесь описаны **два самостоятельных проекта прошивки**. Головки с STM32F722 — подчинённые устройства (slave), ESP32 — ведущее устройство (master) на общей двухпроводной шине RS485. У каждой головки собственный адрес Modbus.

## 1. Какие библиотеки нужны

| Устройство | Протокольный стек | Где находится и как подключается |
|---|---|---|
| STM32 | [FreeModbus](https://github.com/cwalter-at/freemodbus) Christian Walter, версия на коммите `a9ec789a23ff774287e711aeb18492860c8770cf`, лицензия BSD 3-Clause | Нужные исходные файлы **уже добавлены** в `ThirdParty/FreeModbus/` вместе с `LICENSE`. Настройки — `ThirdParty/FreeModbus/include/mbconfig.h`, аппаратная адаптация — `Inc/port.h` и `Src/modbus_port.c`, регистры — `Src/modbus_registers.c`. |
| ESP32 | Официальный компонент Espressif [esp-modbus](https://github.com/espressif/esp-modbus), версия **2.1.4**, лицензия Apache-2.0 |Нужны установленный **ESP-IDF 5.x** (совместимость с IDF ≥ 5.0), доступ к менеджеру компонентов и его зависимостям. |

Оба стека реализуют протокол Modbus RTU; В FreeModbus добавлены две локальные правки: запрет broadcast кроме FC06 holding[0] (SNAP) и преобразование MB_EINVAL в exception 03.

## 3. Прошивка и подключение STM32

Головку STM32 собирают и отлаживают в **IAR EWARM** через совместимый отладчик, подключенный к ее SWD контактам. Для разных головок изменить `MB_SLAVE_ADDRESS`, пересобрать и прошить каждую отдельно. Перед проверкой связи выполнить аппаратную проверку пинов по следующему разделу.

## 4. Проводное подключение и настройки последовательных портов

Оба конца используют **Modbus RTU, 115200 бод, 8 бит данных, чётная чётность, 1 стоп-бит (8E1), двухпроводный полудуплексный RS485**.

В примере **классической ESP32** `esp32_master/main/main.c` использует GPIO17 (UART2 TX -> DI), GPIO16 (UART2 RX <- RO), GPIO4 (UART2 RTS -> DE и /RE). `uart_set_mode(..., UART_MODE_RS485_HALF_DUPLEX)` управляет переключением направления через RTS. 

У каждой головки должен быть **уникальный** Modbus-адрес 1..247 (`MB_SLAVE_ADDRESS`); адрес 0 зарезервирован для вещания. Если адреса совпадают, оба slave ответят одновременно — на RS485 будет коллизия. Адрес задатся при компиляции.

## 5. Команды и порядок опроса

Отображены на стандартные запросы:

| Действие | Запрос Modbus RTU | Действие |
|---|---|---|
| `SNAP(seq=n)` | Адрес устройства **0**, **FC06** (запись одного регистра хранения), адрес регистра **0**, значение `n` | Каждая головка сохраняет последний полностью обработанный кадр. Повтор того же `seq` при `ready=1` не заменяет снимок. |
| `STATUS(id,n)` | Адрес **id**, функция **04** (чтение входных регистров), адреса **0..1** | Возврат `seq`, `ready`. Считать подтверждением только совпадение `seq` и `ready=1`. |
| `READ(id,n)` | Адрес **id**, функция **04**, адреса **0..10** | Возврат сохраненных данных на мастер; Запрашивается, только если статус подтвердили **все** головки. |

FreeModbus вызывает прикладные обработчики с адресом регистра **на 1 больше адреса на линии**: запись по адресу 0 приходит в `eMBRegHoldingCB()` как `address=1`. `Src/modbus_registers.c` учитывает это смещение. Кадрирование, адресацию, CRC16 и паузу тишины t3.5 выполняет библиотека; STM32 отпускает линию (DE=0) только после передачи последнего стоп-бита по флагу TC. 

Номер `seq` — 16-битный счётчик ведущего контроллера. В демонстрации он начинается с 42, увеличивается при каждом цикле и переполняется после 65535. Если ведущий контроллер перезагрузить и начать снова с того же `seq`, подчинённое устройство может принять его за повтор уже подтверждённого кадра. Успешная отправка вещательного запроса **не означает**, что его приняли все: поэтому контроллер отдельно проверяет STATUS каждой головки. Если хотя бы одна не подтвердила запись, весь этап READ пропускается; при ошибке STATUS выполняется одна повторная попытка. Библиотека ESP32 выдерживает после вещания заданную задержку (в примере 150 мс).

### Карта входных регистров функции 04

Каждое поле регистра — 16 бит; для 32-битных полей сначала передаётся старшее слово.

| Адрес | Содержимое |
|---|---|
| 0 | `seq`: номер последнего SNAP, даже если результат оказался невалидным. |
| 1 | `ready`: 1, если обработан хотя бы один кадр, `errorflag=0`, сектор `<144`, угол в `[0,360)`; иначе 0. |
| 2–3 | Угол в **микроградусах**, `uint32` (1° = 1000000; например, 90,500000° = 90500000). |
| 4 | Номер сектора. |
| 5 | `errorflag` алгоритма декодирования. |
| 6 | `encoder_state` — состояние алгоритма калибровки из существующего ПО. |
| 7–8 | Порядковый номер обработанного кадра АЦП, `uint32`. |
| 9–10 | Локальное время головки `HAL_GetTick()`, мс, `uint32`. Часы разных головок **не синхронизированы**. |

Угол переводится из `float` в градусах в `uint32` микроградусов в
`snapshot_publish()`: умножение на 1000000 выполняется в `double`, затем
округление до ближайшего целого (половина вверх). Исходный угол проверяется
на диапазон `[0,360)`; NaN, бесконечность и ошибочные кадры дают `ready=0`.

Master собирает слова 2–3 и выводит градусы
с шестью знаками после запятой, деля целую часть на 1000000 и используя
остаток как дробную часть.

Обработка `SNAP` происходит в основном цикле при `eMBPoll()`, не в прерывании в физический момент фронта на A/B. Каждая головка сохраняет последний **завершенный** результат на момент обработки команды; строго одновременной экспозиции разных головок это не гарантирует. Для полной синхронизации необходим отдельный общий аппаратный сигнал запуска.

## 6. Командный интерфейс калибровки

| Тип | Адрес на линии | Значение |
|---|---|---|
| FC06 holding | 1 | Команда: `0x10` STOP, `0x11` проход 1, `0x12` проход 2, `0x13` offset, `0x14` buf_k |
| FC04 input | `0x100` | Текущий `encoder_state` (0x00..0x80) |
| FC04 input | `0x101` | 1, когда `i2c3_tx_wp != 0`: передача EEPROM завершена, иначе 0 |
| FC04 input | `0x102` | `0xCA01`: сигнатура/версия этого командного интерфейса |

Поддержано чтение поддиапазонов внутри каждого блока, но не через промежуток
11..255. Командные записи только FC06, count=1. Чтения holding/FC16 не включены.
Неизвестная команда/неподготовленный проход 2 → exception 03; занятость автомата
или EEPROM → exception 06; неверный диапазон → exception 02.
**Broadcast разрешен только для SNAP**: калибровочная запись на ID 0 игнорируется
до прикладного callback, без выполнения и без ответа.

### Переключение автоматов STM32 по командам

Цепочка вызовов: `main()` → `eMBPoll()` → `eMBRegHoldingCB()` →
**`encoder_calibration_command()`** в `Src/encoder_calibration.c`.
Обработчик регистров только преобразует результат команды в код Modbus.

| Команда | Подготовка алгоритма | Состояние после команды → после алгоритма |
|---|---|---|
| `0x10` | Снять флаги калибровок, сбросить `cycles_max`; остановить buf_k, фазы offset/anglek = 101, разрешить АРУ | любое → `0x00` |
| `0x11` | `start_calibrate=1`; `angtab_cal()` инициализирует первый проход | `0x10` → `0x20` |
| `0x12` | `start_calibrate=2`; `angtab_cal()` инициализирует второй проход, сохраняя результат первого | `0x30` → `0x40` |
| `0x13` | `start_offset_cal=1`, счётчик усреднений и фаза = 0, **весь `offset_minmax[]=1.0f`**, `offset_cur=offset_start` | `0x50` → `0x60` |
| `0x14` | `start_angk_cal=1`, счётчик усреднений и фаза = 0, `buf_x3[]=0`, запретить АРУ | `0x70` → `0x80` |

Для `0x13` сохраняется настроенное окно `offset_start/offset_end` (исходно 63..65); оно не перезаписывается при каждой команде.

Переход к следующей калибровке выполняется только новой командой; например,
`0x20` само не запускает второй проход. LIVE FC04 читает текущий `encoder_state`,
а не замороженное поле снимка. Коды `0x40/60/80` могут появиться до окончания
I2C-передачи — мастер обязан дополнительно ждать EEPROM_READY.

ESP32 выполняет **14 → 13 → 11 → 12 → 14 → 13** с ожиданием соответственно
**80, 60, 20, 40, 80, 60** и EEPROM_READY. Перед каждым этапом, в том числе
перед следующей головкой, требуется `next`; перед командой `0x12` оператор меняет вращение.
После последнего этапа — `0x10` и проверка состояния `00`.
Проверяются версия интерфейса, исходное состояние, busy/done-коды, тайм-аут
10 минут и ошибки связи. [Полный сценарий и ограничения](../esp32_master/README.md#калибровка).
