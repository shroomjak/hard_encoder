# Modbus RTU по выделенной шине RS-485

Спецификация протокола обмена, карты регистров и конечных автоматов синхронного опроса и калибровки между мастером ESP32 и считывающими головками STM32F722RE.

## 1. Архитектура и состав модулей

Шина RS-485 выделена исключительно под обмен `ESP32 master <-> головки STM32`. Сторонние Modbus-устройства к линии не подключаются.

| Сторона | Модули | Назначение |
|---|---|---|
| STM32F722RE (slave) | `ThirdParty/FreeModbus/` | Vendored стек FreeModbus RTU slave (BSD-3-Clause) с быстрым перехватом `SNAP` в прерывании `t3.5` (`rtu/mbrtu.c`) |
| STM32F722RE (slave) | `Inc/modbus_board.h`, `Src/modbus_port.c` | Аппаратный порт `USART1` (`230400 8E1`), управление `DE`/`/RE`, таймер тишины `TIM2` (`200 мкс`), захват `DWT->CYCCNT` по приёму байта |
| STM32F722RE (slave) | `Inc/encoder_protocol.h` | Общие константы адресов регистров, команд калибровки, сигнатуры `0xCA01` и частоты `DWT` (`216 МГц`) |
| STM32F722RE (slave) | `Inc/snapshot_registers.h`, `Src/snapshot_registers.c` | Двойной буфер последнего валидного кадра `latest_slots[2]`, фиксация среза `frozen` по `SNAP`, расчёт `age_us` и микроградусов без `double` |
| STM32F722RE (slave) | `Inc/encoder_calibration.h`, `Src/encoder_calibration.c` | Приём команд калибровки `0x10..0x14` и взаимоисключающий диспетчер шага `encoder_calibration_step()` |
| STM32F722RE (slave) | `Src/modbus_registers.c` | Обработчики `FC04` (input registers `0..10` и `0x0100..0x0102`) и `FC06` (holding registers `0` и `1`) |
| ESP32 (master) | `esp32_master/main/rs485_rtu.{h,c}` | Прямой детерминированный драйвер RTU поверх `UART2` (`UART_MODE_RS485_HALF_DUPLEX`, `230400 8E1`, без `esp-modbus`) |
| ESP32 (master) | `esp32_master/main/workflow.{h,c}` | Единый автомат режимов `WF_IDLE`, `WF_SCAN`, `WF_POLL`, `WF_CONFIRM`, `WF_CALIB` и оркестратор 4 этапов калибровки |
| ESP32 (master) | `esp32_master/main/pc_link.{h,c}` | 64-битная скоростная компенсация `age_us -> t_snap`, буфер `RINGBUF_TYPE_NOSPLIT` (`64 КБ`) и форматирование `DATA` на Core 1 |
| ESP32 (master) | `esp32_master/main/main.c` | Изоляция ядер Core 0 (`encoder_bus` + `esp_timer` ISR `100 Гц`) и Core 1 (`UART0` `921600 8N1` на шине `APB`, консоль `esp_console`) |

## 2. Физический и канальный уровень

| Параметр | STM32F722RE (`Inc/modbus_board.h`) | ESP32 (`esp32_master/main/main.c`) |
|---|---|---|
| Интерфейс UART | `USART1` (`PB6 = TX`, `PB7 = RX`) | `UART2` (`GPIO17 = TX`, `GPIO16 = RX`) |
| Управление трансивером | `PB5 = DE`, `PB4 = /RE` (переключение по флагу `TC`) | `GPIO4 = RTS` (`DE` и `/RE` объединены, аппаратный `HALF_DUPLEX`) |
| Скорость и формат кадра | `230400` бод, `8E1` (`LL_USART_DATAWIDTH_9B` + `EVEN`, `11` бит = `47.74 мкс/байт`) | `230400` бод, `8E1`, `UART_SCLK_DEFAULT` (`APB = 80 МГц`) |
| Детектор конца кадра `t3.5` | `TIM2`: `1 МГц`, `ARR = 199` (`200 мкс`) | Пауза после `SNAP`: `300 мкс`; межкадровый зазор между головками: `250 мкс` |
| Адресация ведомых | `MB_SLAVE_ADDRESS` в `[1, 247]` (уникален для каждой платы) | Широковещательный адрес `0` — только для `SNAP` |
| Канал ESP32 -> ПК | — | `UART0`, `921600 8N1`, принудительный `UART_SCLK_DEFAULT` (`922190` бод, `+0.064%`) |

Требования к аппаратной линии: общий `GND` между трансиверами, дифференциальная витая пара `A/B`, терминаторы `120 Ом` на концах шины, смещение (fail-safe bias) на неактивной линии.

## 3. Сборка и прошивка

### STM32F722RE (IAR Embedded Workbench for ARM)
1. В `Inc/modbus_board.h` задать уникальный `MB_SLAVE_ADDRESS` (`1..247`) и сверить выводы `MB_TX/RX/DE/NRE` со схемой платы.
2. Открыть `EWARM/Project.eww`, выполнить **Project -> Rebuild All** и **Download and Debug** через ST-LINK.
3. Повторить для каждой считывающей головки со своим `MB_SLAVE_ADDRESS`.

### ESP32 (ESP-IDF v5.x)
```bash
cd esp32_master
idf.py set-target esp32
idf.py build
idf.py -p <PORT> flash monitor
```
Консоль `idf.py monitor` и скрипт `diagnostics/serial_head_logger.py` работают на скорости `921600 8N1` (задано в `esp32_master/sdkconfig.defaults`: `CONFIG_ESPTOOLPY_MONITOR_BAUD=921600`, `CONFIG_ESP_CONSOLE_UART_BAUDRATE=921600`).

## 4. Карта регистров Modbus

В таблицах указаны **0-базовые адреса PDU** (передаваемые в поле адреса RTU-кадра). Внутри callback-функций FreeModbus используется `usAddress = pdu_address + 1`.

### Holding Registers (`FC 0x06` — Write Single Register, только запись)

| PDU-адрес | Имя | Допустимая адресация | Назначение |
|---:|---|---|---|
| `0x0000` (`0`) | `SNAP_COMMAND` | Только broadcast (`ID = 0`) | Записываемое слово `seq` фиксирует срез `frozen` одновременно на всех головках без ответа в линию; при адресном вызове возвращается исключение `0x03` (`MB_EINVAL`) |
| `0x0001` (`1`) | `ENCODER_CAL_COMMAND` | Только unicast (`ID = 1..247`) | Команда калибровки `0x0010..0x0014`; широковещательный вызов игнорируется |

Коды исключений при записи `ENCODER_CAL_COMMAND`:
* `0x03` (`Illegal Data Value` / `MB_EINVAL`) — неизвестный код команды либо запрос `0x0012` (проход 2 `ang_tab`) вне состояния `0x0020`.
* `0x06` (`Slave Device Busy` / `MB_ETIMEDOUT`) — уже выполняется калибровка либо не завершена фоновая запись EEPROM (`i2c3_tx_wp == 0`).

### Input Registers `0x0000..0x000A` (`FC 0x04` — зафиксированный снимок `SNAP`)

Регистры возвращают содержимое буфера `frozen`, защёлкнутого последней командой `SNAP`. Текущие кадры линейки обновляют только `latest_slots[2]` и не изменяют `frozen` до следующего `SNAP`. Чтение за пределами `0..10` возвращает исключение `0x02` (`Illegal Data Address`).

| PDU-адрес | Константа | Тип | Содержимое |
|---:|---|---|---|
| `0` | `SNAP_SEQ` | `uint16` | Номер `seq`, принятый в последнем `SNAP` |
| `1` | `SNAP_READY` | `uint16` | `1` — в `frozen` зафиксирован достоверный кадр (`error == 0`, `sector < 144`, `angle ∈ [0, 360)`); `0` — данные невалидны |
| `2` | `SNAP_ANGLE_HI` | `uint32` (старшее слово) | Угол `angle_udeg` в микроградусах (`0..359 999 999`), масштабированный целочисленно из мантиссы IEEE-754 `float` без `double` |
| `3` | `SNAP_ANGLE_LO` | `uint32` (младшее слово) | Младшие 16 бит `angle_udeg`; при `ready == 0` значение не используется |
| `4` | `SNAP_SECTOR` | `uint16` | Номер сектора `0..143` на момент кадра |
| `5` | `SNAP_ERROR` | `uint16` | Флаг `errorflag` зафиксированного кадра (`0` — норма) |
| `6` | `SNAP_ENCODER_STATE` | `uint16` | Код `encoder_state` на момент фиксации |
| `7` | `SNAP_SAMPLE_HI` | `uint32` (старшее слово) | Монотонный счётчик обработанных кадров линейки `sample_counter` |
| `8` | `SNAP_SAMPLE_LO` | `uint32` (младшее слово) | Младшие 16 бит `sample_counter` |
| `9` | `SNAP_TIME_HI` | `int32` (старшее слово) | Знаковый возраст экспозиции `age_us = round((snap_rx_cyccnt - exp_cyccnt) / 216)` в микросекундах (`DWT->CYCCNT`, `216 МГц`) |
| `10` | `SNAP_TIME_LO` | `int32` (младшее слово) | Младшие 16 бит `age_us` |

### Input Registers `0x0100..0x0102` (`FC 0x04` — `LIVE`-диагностика калибровки)

Читаются адресно без `SNAP` и не затрагивают буфер `frozen`.

| PDU-адрес | Константа | Значение |
|---:|---|---|
| `0x0100` (`256`) | `ENCODER_CAL_STATE` | Текущий `encoder_state` (`0x00`, `0x10`, `0x20`, `0x30`, `0x40`, `0x50`, `0x60`, `0x70`, `0x80`) |
| `0x0101` (`257`) | `ENCODER_EEPROM_READY` | Флаг `i2c3_tx_wp`: `1` — шина I2C3 свободна и защита записи `WP` (`PA9`) включена; `0` — идёт запись EEPROM либо произошёл сбой I2C |
| `0x0102` (`258`) | `ENCODER_CAL_VERSION` | Сигнатура интерфейса калибровки `0xCA01` (`ENCODER_CAL_MAGIC`) |

## 5. Синхронный рабочий цикл `poll`

Опрос выполняется задачей `encoder_bus` на изолированном ядре Core 0 по прерыванию аппаратного таймера `esp_timer` (`ESP_TIMER_ISR`), период по умолчанию — `10 000 мкс` (`100.000 Гц` для `1..3` головок; при `>= 4` головках `choose_poll_period_us()` увеличивает период кратно `1 мс` исходя из бюджета `700 + 2350 * N` мкс).

Последовательность одного цикла `seq`:
1. **Широковещательный `SNAP`**: передача 8 байт `00 06 00 00 seq_hi seq_lo crc_lo crc_hi` (`~382 мкс` на линии), фиксация метки мастера `t_us` сразу по `uart_wait_tx_done()` и выдержка `RS485_SNAP_SETTLE_US = 300 мкс`.
2. **Фиксация на головках STM32**: стоп-бит последнего байта `SNAP` сохраняет `snap_rx_cyccnt = DWT->CYCCNT` (в `USART1_IRQHandler` либо через неразрушающий опрос `modbus_poll_rx_cyccnt()` внутри критической секции `DMA2_Stream3_IRQHandler`). По истечении `TIM2` (`t3.5 = 200 мкс`) функция `xMBRTUTimerT35Expired()` проверяет CRC пакета `SNAP` и непосредственно в прерывании вызывает `snapshot_latch(seq)`. Чужие адресные кадры отбрасываются в `TIM2_IRQHandler` без постановки событий в `eMBPoll()`.
3. **Поочерёдное чтение `FC 0x04`**: мастер запрашивает у каждой выбранной головки `11` регистров `0..10` одним пакетом (ответ `27` байт, порог пробуждения `UART2 RX FIFO = 27` байт, таймаут `3.5 мс`). Между соседними головками выдерживается зазор `250 мкс`.
4. **Валидация и приведение к `t_snap`**: проверяются условия `r[0] == seq`, `r[1] == 1`, `sector < 144`, `error == 0`, `raw_angle < 360 000 000` и `age_us ∈ [-500, +2500]`. Функция `pc_sync_compensate_udeg()` линейно экстраполирует угол со времени экспозиции кадра `t_us - age_us` к общему моменту `t_us` в 64-битной знаковой целочисленной арифметике микроградусов.
5. **Выдача в ПК (Core 1)**: запись передаётся через `RINGBUF_TYPE_NOSPLIT` задаче `pc_link`, формирующей строку:
   ```text
   DATA seq=<u16> t_us=<u64> snap_us=<u32> poll_us=<u32> error=<mask> id=<id> ang=<deg|nan> raw_ang=<deg|nan> age_us=<i32> read_us=<u32> gap_us=<u32> ...
   ```

## 6. Режим калибровки `calib`

### Единая точка оркестрации и взаимное исключение

* **Оркестрация последовательности** сосредоточена исключительно в `esp32_master/main/workflow.c`. Во время `WF_CONFIRM` и `WF_CALIB` периодический таймер `SNAP` и рабочий опрос `poll` остановлены.
* **Исполнение на STM32** централизовано в `Src/encoder_calibration.c`: `encoder_calibration_command()` запускает не более одного автомата при `i2c3_tx_wp == 1`, а `encoder_calibration_step()` в суперцикле `main()` продвигает единственный активный автомат и принудительно сбрасывает все автоматы в `STOP` при любой коллизии флагов.
* **Темп опроса в `WF_CALIB`**: мастер читает `LIVE`-регистры `0x0100..0x0102` с периодом `50 мс` (`20 Гц`), не перегружая `USART1` головки во время накопления оптических отсчётов и оставляя процессорное время задаче `IDLE0` (защита от Task Watchdog), при мгновенном приёме команды `stop` из очереди.

### Строгий порядок 4 этапов на каждую головку

| Шаг | Команда `FC06` | Процедура STM32 | `busy` -> `done` | Требование к вращению вала | Физическая зависимость |
|---:|---|---|---|---|---|
| 1 | `0x0014` | `angk_cal()` (`buf_k[6..126]`) | `0x70 -> 0x80` | Равномерно, любое направление, `10..40 об/мин` | Выравнивает чувствительность всех рабочих пикселей до расчёта субпиксельных координат `s_l1`, `s_l2` |
| 2 | `0x0013` | `offset_cal()` (`offset`) | `0x50 -> 0x60` | Равномерно, любое направление, `10..40 об/мин` | Находит оптический центр съёма по минимуму `min_max` на уже скорректированных реперах |
| 3 | `0x0011` | `angtab_cal()` проход 1 | `0x10 -> 0x20` | В сторону **возрастания** выходного угла, `5..20 об/мин` | Измеряет ширины секторов в симметричном стробе относительно найденного `offset` |
| 4 | `0x0012` | `angtab_cal()` проход 2 | `0x30 -> 0x40` | В **противоположную** сторону (убывание угла), `5..20 об/мин` | Усредняет два направления обхода, замыкает шкалу `360°` и сохраняет `ang_tab[144]` в EEPROM |

После завершения шага 4 (`state == 0x40` и `EEPROM_READY == 1`) мастер отправляет `0x0010` (`STOP`) и проверяет переход `state == 0x00` по `LIVE`-чтению. Повторный запуск `0x14` или `0x13` после расчёта `ang_tab` не выполняется, так как изменение `buf_k` или `offset` без пересчёта `ang_tab` нарушает геометрическое согласование таблицы секторов с точкой съёма.

### Правила безопасности автомата `workflow.c`
* Перед каждым этапом и перед переходом к следующей головке требуется ручное подтверждение `next`.
* Перед отправкой `FC06` проверяются `ENCODER_CAL_VERSION == 0xCA01`, `EEPROM_READY == 1` и ожидаемое исходное состояние (`0x00` перед шагом 1, `done` предыдущего шага перед шагами 2–4).
* Потеря ответа `FC06` не вызывает автоматического повтора команды запуска; список прерывается с отправкой `STOP` и проверкой `LIVE`.
* Таймаут одного этапа — `600 с`; `5` последовательных ошибок `LIVE`-чтения (`250 мс`) аварийно завершают калибровку с отправкой `STOP`.

## 7. Ограничения реализации

1. **Страничная запись I2C EEPROM**: блоки `ang_tab` (`578` байт) и `buf_k` (`514` байт) передаются одним вызовом `HAL_I2C_Mem_Write_IT()`. Если применённая на плате микросхема `AT24Cxx` имеет аппаратный буфер страницы `16..64` байт, запись длиннее страницы заворачивается внутри неё, и при следующем включении `init_vars()` отбраковывает блок по `CRC16` (`*_rdy == 0`). После калибровки обязательна проверка `ang_tab_rdy == 1`, `buf_k_rdy == 1`, `offset_rdy == 1` после перезагрузки головки.
2. **Отказ шины I2C**: при ошибке обмена `HAL_I2C_ErrorCallback()` выставляет `i2c3_err = 1` и возвращает аппаратную защиту записи `WP` (`PA9 = 1`), оставляя `i2c3_tx_wp = 0`, чтобы мастер зафиксировал незавершённость записи EEPROM по таймауту.
3. **Команда `STOP` (`0x0010`)**: останавливает автоматы калибровки и возвращает разрешение АРУ (`backlight_width_en = 1`), но не откатывает уже изменённые в ОЗУ массивы `buf_k`, `offset`, `ang_tab` и не прерывает текущую транзакцию `I2C3`.
