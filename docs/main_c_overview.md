# Технический обзор прошивки считывающей головки (`Src/main.c`)

Поблочное описание аппаратных узлов, приоритетов прерываний, конвейера обработки кадра и конечных автоматов самокалибровки модуля считывающей головки на микроконтроллере **STM32F722RETx** (ARM Cortex-M7, `216 МГц`, одинарный FPU `FPv5-SP-D16`, сборка в IAR EWARM `EWARM/Project.eww`).

Связанные документы:
* [`modbus_rtu.md`](modbus_rtu.md) — протокол RS-485 / Modbus RTU, карта регистров и взаимодействие с мастером ESP32.
* [`angle_math_and_calibration.md`](angle_math_and_calibration.md) — математическая модель вычисления угла, бюджет погрешностей и алгоритмы калибровки.
* [`README.md`](README.md) — сквозная архитектура тракта `STM32 -> ESP32 -> ПК` и инженерный разбор устранённых дефектов.

## 1. Назначение и основные параметры головки

Оптический кодовый диск содержит `BIT_TAB_SIZE = 144` сектора с номинальным шагом `2.5°` (`9000″`). В каждом секторе нанесены узкая светлая реперная метка (~3 пикселя) и уникальный 9-битный код сектора. Светодиод подсветки (`PA15`) проецирует участок диска на КМОП-фотолинейку **TSL1401CL** (`128` пикселей, шаг `63.5 мкм`). В поле зрения одновременно попадают два соседних репера на расстоянии около `SECTOR_SIZE = 51` пикселя (`1 пиксель ≈ 0.04902° ≈ 176.5″`).

Прошивка решает три задачи:
1. Детерминированно опрашивает фотолинейку с периодом кадра `T ≈ 103 мкс` (`~9.7 кГц`) и фиксирует тактовую метку середины оптической экспозиции по свободно бегущему счётчику `DWT->CYCCNT` (`216 МГц`).
2. За фиксированное время `O(1)` (`~30..45 мкс` на кадр) вычисляет угол вала `[0°, 360°)` и публикует кадр в неблокирующий двойной буфер `latest_slots[2]`.
3. Обслуживает выделенную шину RS-485 (`Modbus RTU`, `230400 8E1`): мгновенно защёлкивает снимок по широковещательной команде `SNAP` в прерывании таймера `TIM2` и исполняет атомарные этапы самокалибровки по адресным командам мастера.

## 3. Считывание кадра `TSL1401CL` и метка экспозиции

Цикл линейки состоит из `132` тактов `T-CLK` (`80.67 мкс`: `2` стартовых холостых такта, `128` фотодиодов, `2` завершающих такта) и обработчика `DMA2_Stream3_IRQHandler` (`~22.5 мкс`), суммарно `T ≈ 103 мкс`.

Последовательность действий в `DMA2_Stream3_IRQHandler`:
1. Запрет прерываний (`__disable_irq()`), сброс флага `TC3`, инвалидация `D-Cache` для `ADC_VAL` и `ADC_VAL2`.
2. Синхронное ожидание спада `132`-го импульса на `PC6` и останов `TIM3`.
3. Пауза `DelayTim4Ticks(2160)` (`tqt = 20.00 мкс`); внутри цикла ожидания вызывается `modbus_poll_rx_cyccnt()` для захвата метки `USART1 RXNE` с точностью `< 0.7 мкс` без чтения `RDR`.
4. Выдача `SI = 1` (`PC7`), чтение `si_cyccnt = DWT->CYCCNT`, запуск одновибратора подсветки `Backlight_StartFromSI()`, запуск `TIM3` и снятие `SI = 0` после первого фронта `T-CLK`.
5. Расчёт метки середины будущей вспышки (`1 тик TIM4 = 2 такта DWT`):
   `new_exp_cyccnt = si_cyccnt + 2 * backlight_delay_ticks + backlight_width_ticks`.
   Поскольку `TSL1401CL` выдаёт на выход `AO` заряд, накопленный за два импульса `SI` до завершения текущего буфера DMA, метки проходят через двухтактный конвейер `exp_cyccnt_pipe[2]`.
6. Копирование `128` отсчётов завершённого буфера DMA (со смещением `+2`) в `buf_x0[128]`, запись `buf_x0_exp_cyccnt`, барьер `__DMB()`, установка `adc_rdy = 1` и разрешение прерываний (`__enable_irq()`).

В штатной конфигурации при старте `main()` автоматическая регулировка подсветки отключена (`agc_test_disable = 1U`, `backlight_width_ticks = 2000`), поэтому положение и длительность окна экспозиции (`18.52 мкс`) строго постоянны.

## 4. Конвейер обработки кадра в суперцикле `main()`

На каждой итерации `while (1)` при `adc_rdy == 1` последовательно выполняются этапы константной сложности `O(1)`:

| Шаг | Функция | Входные данные | Результат и ключевые детали реализации |
|---:|---|---|---|
| 1 | `copy_data()` | `buf_x0[128]`, `adc_offset = 600`, `config_state`, `buf_k[128]` | Заполняет `buf_x1[1..126]` (при `config_state == 1` — в обратном порядке `127 - i`), находит `max_data` / `min_data`; при `anglek_phase < 4` обновляет пиковый детектор `buf_x3[1..126]`. Индексы `0` и `127` не обновляются |
| 2 | `find_startpixel()` | `buf_x1[128]` | Строит префиксные суммы `pref[0..128]` и за `O(1)` на сдвиг вычисляет двухреперную корреляцию `scor[i]` на `i ∈ [6, 57)` (охват пикселей `6..126`). Выбирает более острый пик, формирует пару `startpixel1 ∈ [6..56]` и `startpixel2 = startpixel1 + 51 ∈ [57..107]` |
| 3 | `mes_piks()` + `BR4_C()` | `startpixel1`, `startpixel2`, `buf_x1`, `buf_k` | Формирует `buf_x2[i] = buf_x1[i] * buf_k[i]` в расширенном окне `[star_pixel + 1, star_pixel + 19)` (`7..125`), ищет максимум `max_X0` в `[star_pixel + 4, star_pixel + 16)` (`10..122`) и вычисляет субпиксельные координаты `s_l1`, `s_l2` 6-точечным балансным ядром `[max_X0 - 3 .. max_X0 + 3]` с синусоидальной поправкой `k_comp = 0.01` (`arm_sin_f32`) |
| 4 | `find_datablock()` | `s_l1`, `s_l2`, `buf_x1` | Строит адаптивную сетку `pix_size = (s_l2 - s_l1) / 15`, находит локальные уровни белого/чёрного на `[startpixel1 + 14, startpixel1 + 51)` и линейной интерполяцией `get_pix()` вычисляет мягкие метрики `pix[9][2]` для 9 информационных бит |
| 5 | `calc_sector()` | `pix[9][2]` | Собирает 9-битное слово `data_byte`, определяет индекс наименее достоверного бита `badbit_pos` (`badbit_value = min |pix[i][1] - pix[i][0]|`) и за одно обращение к Flash-таблице `sector_by_code[512]` получает `rem_sec` (`0..143` или `255`) |
| 6 | `err_corr()` + `bit_err_corr()` | `rem_sec`, `sector_history_valid` | Проверяет попадание `rem_sec` в окно непрерывности `{lsec, cursec, rsec}`. При расхождении и валидной истории выполняет `O(1)` инверсию бита `0x100U >> badbit_pos` (при `badbit_value < 1000`) и повторную выборку из `sector_by_code[512]`. При неисправимом сбое выставляет `errorflag = 1`, `serrcnt1++` и сбрасывает `sector_history_valid = 0` |
| 7 | `calc_ang()` | `sector`, `s_l1`, `s_l2`, `offset`, `ang_tab[144]` | Выполняется только при `errorflag == 0`. Интерполирует угол внутри сектора с индивидуальным масштабом `k_pix = angle_dif / (s_l2 - s_l1)` и записывает результат `[0, 360)` в `cur_ang_X` (`cur_ang_E`) |
| 8 | `find_avg()` + `encoder_calibration_step()` | `cur_ang_X` | При `errorflag == 0` обновляет скользящее окно 30 кадров, метрику `min_max`, счётчик оборотов `avg_minmax_num` и вызывает взаимоисключающий диспетчер активного этапа калибровки |
| 9 | `snapshot_publish_timed()` | `cur_ang_E`, `sector`, `errorflag`, `encoder_state`, `frame_exp_cyccnt` | Неблокирующе публикует кадр в `latest_slots[2]`. Вне блока `adc_rdy` суперцикл выполняет до двух шагов `eMBPoll()` за проход |

В файле присутствуют альтернативные функции оценки центра пятна (`BR4`, `BR4_F`, `BR6`, `BR6_F`, `BR8`, `INTEGRAL`, `KVADRATURA`, `CENTR_OF_MASS`, `calc`, `Fast2ArcTan`) и коррекции репера (`startpixel_err_corr`); в рабочем тракте они не вызываются.

## 5. Карта внешней памяти EEPROM (`I2C3`)

При старте `init_vars()` считывает весь объём `eeprom_len = 2048` байт в `eeprom_buf[]` и независимо проверяет `CRC16` каждого блока (`crc_16_step()`). При совпадении контрольной суммы блок копируется в рабочую переменную с установкой флага `*_rdy = 1`; иначе сохраняется таблица по умолчанию из Flash.

| Блок | Смещение в `eeprom_buf` | Адрес I2C страницы | Размер с `CRC16` | Флаг загрузки | Кто записывает |
|---|---:|---|---:|---|---|
| `ang_tab[144]` | `0` (`CRC` @ `576`) | `EEPROM_DEVICE_PAGE0` (`0xA0`) | `576 + 2 = 578` байт | `ang_tab_rdy` | `angtab_cal()` (завершение прохода 2) |
| `buf_k[128]` | `768` (`CRC` @ `1280`) | `EEPROM_DEVICE_PAGE3` (`0xA6`) | `512 + 2 = 514` байт | `buf_k_rdy` | `angk_cal()` (`anglek_phase == 100`) |
| `offset` | `1536` (`CRC` @ `1540`) | `EEPROM_DEVICE_PAGE6` (`0xAC`) | `4 + 2 = 6` байт | `offset_rdy` | `offset_cal()` (`offset_phase == 100`) |
| `lasdac` | `1544` (`CRC` @ `1546`) | `EEPROM_DEVICE_PAGE6` (`0xAC`) | `2 + 2 = 4` байт | `lasdac_rdy` | Наследие ЦАП (в текущей ревизии не перезаписывается) |

Аппаратная защита записи `WP` (`PA9`) снимается (`0`) перед `HAL_I2C_Mem_Write_IT()` и возвращается (`1`) в `HAL_I2C_MemTxCpltCallback()` (с установкой `i2c3_tx_wp = 1`) либо в `HAL_I2C_ErrorCallback()` (с установкой `i2c3_err = 1` и сохранением `i2c3_tx_wp = 0`).

## 6. Управление самокалибровкой (`Src/encoder_calibration.c` и `Src/main.c`)

Головка не содержит встроенного сценария многоэтапной калибровки: очерёдность этапов (`0x14 -> 0x13 -> 0x11 -> 0x12 -> 0x10`) задаётся исключительно мастером ESP32 (`esp32_master/main/workflow.c`). На стороне STM32 модуль `Src/encoder_calibration.c` обеспечивает:
* запуск команд `0x11..0x14` только при отсутствии активных автоматов и завершённой записи EEPROM (`i2c3_tx_wp == 1`);
* допуск команды `0x12` (проход 2 `ang_tab`) строго из состояния `encoder_state == 0x20`;
* вызов ровно одного активного автомата за кадр через `encoder_calibration_step()` и аварийный сброс всех автоматов в `STOP` (`0x10`), если более одного стартового флага оказались выставлены одновременно.

| Команда | Функция | Калибруемый параметр | Особенности реализации в `Src/main.c` |
|---|---|---|---|
| `0x14` | `angk_cal()` | `buf_k[128]` (`0x70 -> 0x80`) | Сбрасывает `buf_k[0..127] = 1.0f` и `buf_x3[0..127] = 0.0f`; выравнивает **весь рабочий диапазон пикселей `[6..126]`** с защитой от деления на ноль (`ANGK_MIN_VALID_PEAK = 50.0f`, ограничение усиления `[0.25, 4.0]`); очищает пиковый детектор `buf_x3` после каждого шага пересчёта; ограничивает фазу 2 лимитом `ANGK_PHASE2_MAX_ITERS = 5`; подбирает усиление (`1.00g, 1.04g, 1.0816g`) для 3 наиболее ослабленных пикселей зоны `[10..122]` |
| `0x13` | `offset_cal()` | `offset` (`0x50 -> 0x60`) | Перебирает целые координаты в окне `[offset_start, offset_end]` (`[63, 65]`), при попадании минимума `min_max` на край окна расширяет поиск на `offset_snum = 7` шагов наружу (`[56, 65]` или `[63, 72]`) без повторного измерения внутренних точек |
| `0x11`, `0x12` | `angtab_cal()` | `ang_tab[144]` (`0x10 -> 0x20`, `0x30 -> 0x40`) | Накапливает по `pix_dif_num_avg = 5` измерений ширины каждого сектора в симметричном стробе `[offset - 25..24]` / `[offset + 24..25]` при вращении в противоположных направлениях, замыкает сумму на `360°` и усредняет две таблицы |
| `0x10` | `STOP` | Все автоматы (`-> 0x00`) | Останавливает все процедуры, переводит `offset_phase = anglek_phase = 101`, возвращает `backlight_width_en = 1`, обнуляет `cycles_max` |
