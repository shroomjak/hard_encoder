# `Src/main.c` — поблочное техническое описание

> Документ рассчитан на читателя с сильной математической подготовкой, но с небольшим опытом embedded-разработки.
> Все прикладные термины помечены и снабжены короткой справкой «зачем это здесь» + ссылкой на первоисточник.
> Всё изложенное опирается строго на код в `Src/main.c` текущей ветки.
>
> Математика алгоритмов (поиск репера, декодирование сектора, коррекция ошибок, самокалибровка)
> вынесена в отдельный документ: **[`angle_math_and_calibration.md`](angle_math_and_calibration.md)**.

## 0. Что это за устройство

Проект — **считывающая головка абсолютного оптического датчика угла (энкодера)**.

| Параметр | Значение | Откуда в коде |
|---|---|---|
| Микроконтроллер | **STM32F722RETx** (ARM Cortex-M7, 216 МГц) | `taos.ioc`: `Mcu.UserName=STM32F722RETx` |
| Фотоприёмник | линейка **TSL1401CL**, 128 пикселей, шаг 63.5 мкм | `TSL1401_TQT_US`, `MX_TIM3_Init`, `DMA2_Stream3_IRQHandler` |
| Число секторов диска | **144** (360°/144 = 2.5° на сектор) | `#define BIT_TAB_SIZE 144` |
| Расстояние между реперами | **51 пиксель** | `#define SECTOR_SIZE 51` |
| Код сектора | **9 бит**, таблица `bit_tab[144]` | `calc_sector()` |
| Выход | угол `float` [0; 360) по **SPI** | `spi_SendExec()`, `cur_ang_E` |
| Энергонезависимые данные | **EEPROM** по **I2C3** (2 КБ) | `init_vars()`, карта `eeprom_*` |
| Обновление ПО | внешняя **SPI-Flash** AT25SF641 | `SloComProcess()`, `Drivers/FLASH` |

Косвенные оценки, вытекающие из констант (расчёт — см. математический документ):

* 1 пиксель линейки ≈ **0.049° = 176.5 угловых секунд**;
* частота кадров ≈ **9.9 кГц** (период ≈ 101 мкс);
* диаметр кодовой дорожки при оптике 1:1 ≈ **148 мм**.

## 3. Блок «константы и геометрия»

```c
#define MAX_LEVEL_PIX           3700      // целевая "полка" яркости в отсчётах АЦП (АРУ)
#define ADC_OFFSET              600       // тёмновой уровень, вычитается из каждого пикселя

#define BIT_TAB_SIZE            144       // число секторов диска
#define SECTOR_SIZE             51        // номинальное расстояние между реперами, пиксели
#define BITS_PER_SECTOR         15        // на сколько битовых ячеек делится сектор
```

* **`MAX_LEVEL_PIX = 3700`** при 12-битном АЦП (максимум 4095) — запас ~10 % до насыщения.
  Насыщение недопустимо: субпиксельный алгоритм требует **неискажённой формы** светового пятна.
* **`ADC_OFFSET = 600`** — пьедестал (тёмновой ток + смещение тракта). Вычитается в `copy_data()`,
  затем автоматически подстраивается в `dac_ctrl()`: `adc_offset = avg_max_data / 5`.
* **`SECTOR_SIZE = 51`** связывает «пиксели» и «градусы»: 2.5° ↔ 51 пиксель.

```c
#define APB1_TIMER_CLOCK_HZ   108000000UL  // тактовая частота таймеров шины APB1
#define TSL1401_TQT_US        20UL         // tqt из даташита TSL1401CL
#define TSL1401_TQT_TIM_TICKS (APB1_TIMER_CLOCK_HZ / 1000000UL * TSL1401_TQT_US)  // = 2160 тиков

#define STARTPIXEL_MIN        6
#define STARTPIXEL_MAX        57
#define CENTER_PIXEL          60
```

* **`STARTPIXEL_MAX = 57`** — не произвольное число: шаблон корреляции в `find_startpixel()`
  обращается к `buf_x1[i+69]`, и `57 + 69 = 126 < 128` — ровно граница массива.
* **`CENTER_PIXEL = 60`** — «водораздел»: найденный репер правее 60-го пикселя считается
  **правым** репером пары, левее — **левым**. Нужно, чтобы однозначно достроить второй репер
  как `startpixel ± SECTOR_SIZE`.

### Карта EEPROM

```c
#define eeprom_len            2048                 // полный объём (2 КБ)

#define eeprom_ang_tab        0x00                 // таблица углов секторов, 144*4 = 576 байт
#define eeprom_ang_tab_crc    BIT_TAB_SIZE*4       // = 576, CRC16 таблицы

#define eeprom_buf_k          768                  // коэффициенты пикселей, 128*4 = 512 байт
#define eeprom_buf_k_crc      1280

#define eeprom_offset         1536                 // точка съёма угла, 4 байта (float)
#define eeprom_offset_crc     1540
#define eeprom_lasdac         1544                 // уставка ЦАП (не используется), 2 байта
#define eeprom_lasdac_crc     1546
```

Адреса `EEPROM_DEVICE_PAGE0…7` (`0xA0, 0xA2, … 0xAE`) — это **разные I2C-адреса одного кристалла**,
классическая организация памяти 16 Кбит (8 блоков по 256 байт), где старшие биты адреса
передаются в адресном байте устройства. Каждый блок данных сопровождается **CRC16**,
которая проверяется при старте в `init_vars()`.

## 4. Блок «буферы изображения»

Данные проходят через цепочку буферов — понимать её важно, иначе код выглядит хаотично:

| Буфер | Тип | Содержимое | Кто заполняет |
|---|---|---|---|
| `ADC_VAL[132]`, `ADC_VAL2[132]` | `uint16_t` | сырые отсчёты АЦП, двойная буферизация DMA | DMA2 Stream3 (аппаратно) |
| `buf_x0[128]` | `uint16_t` | копия кадра (пропущены 2 служебных отсчёта) | `DMA2_Stream3_IRQHandler()` |
| `buf_x1[128]` | `uint16_t` | кадр без пьедестала: `buf_x0[i] - adc_offset`, ≥ 0 | `copy_data()` |
| `buf_x2[128]` | `float` | `buf_x1[i] * buf_k[i]` — с учётом неравномерности пикселей | `mes_piks()` |
| `buf_x3[128]` | `float` | **пиковый детектор** яркости каждого пикселя | `copy_data()` при `anglek_phase < 4` |
| `buf_x4`, `buf_x5` | — | **не используются** | — |

Атрибут `__attribute__((aligned(32)))` на DMA-буферах — не украшение: операции с кэшем
Cortex-M7 (`SCB_InvalidateDCache_by_Addr`) работают **строками по 32 байта**, и невыровненный
буфер привёл бы к инвалидации чужих данных.

## 5. Блок «кодовая таблица» `bit_tab[144]`

```c
const uint16_t bit_tab[BIT_TAB_SIZE] = { 197, 314, 213, 298, 85, 426, ... 306 };
```

`bit_tab[j]` — 9-битный код (0…511), физически нанесённый на сектор `j`.
Декодирование — **линейный поиск** значения в таблице, индекс = номер сектора (`calc_sector()`).

Свойства таблицы (посчитаны по фактическим данным файла):

* все 144 значения **уникальны**;
* минимальное расстояние Хэмминга **по всей таблице равно 1** → код **не является помехоустойчивым**;
* но коды **соседних** секторов отличаются на **5…9 бит** (72 пары по 8 бит, 70 пар по 9 бит,
  одна пара по 7 и одна по 5).

Это ключевой момент для понимания архитектуры защиты от ошибок:
**одиночный битовый сбой не может превратить сектор `j` в сектор `j±1`**,
поэтому проверка непрерывности номера сектора во времени (`err_corr()`) работает как мощный
детектор ошибок, компенсируя отсутствие избыточности в самом коде.

В конце таблицы видны закомментированные значения (`//327, //184, //455, //56, //454`) —
кодовая последовательность была обрезана до ровных 144 элементов.

## 6. Конвейер обработки кадра

Один проход `while(1)` в `main()` = один кадр линейки. Последовательность жёстко фиксирована:

```c
if (adc_rdy == 1) {
  copy_data();                 // предобработка кадра
  find_startpixel();           // поиск репера
  s_l1 = mes_piks(startpixel1);// субпиксельная координата левого репера
  s_l2 = mes_piks(startpixel2);// субпиксельная координата правого репера
  find_datablock();            // выборка 9 бит кода
  calc_sector();               // декодирование номера сектора
  err_corr();                  // контроль и коррекция ошибок

  if (errorflag == 0) {
    calc_ang();                // УГОЛ
    find_avg();                // метрика качества
    offset_cal();              // самокалибровка offset
    angk_cal();                // самокалибровка buf_k
    angtab_cal();              // самокалибровка ang_tab
    cur_ang_E = cur_ang_X;     // наружу уходит только достоверное значение
  }

  spi_SendExec();              // отправка кадра SPI
  dac_ctrl();                  // АРУ подсветки
  SloComProcess();             // медленные команды (прошивка)
  ... расчёт температуры, чтение DWT ...
  adc_rdy = 0;
}
```

### 6.1 `copy_data()` — предобработка

1. Вычитает `adc_offset`, обрезая отрицательные значения в 0 → `buf_x1`.
2. Находит `max_data` и `min_data` по кадру — **опорные уровни** для корреляционного детектора.
3. Если идёт калибровка `buf_k` (`anglek_phase < 4`), ведёт **пиковый детектор**
   `buf_x3[i] = max(buf_x3[i], buf_x1[i] * buf_k[i])`.

Важная деталь — **`config_state`**: перемычка на `PB8`, прочитанная в `init_vars()`.
При `config_state == 1` кадр переписывается в **обратном порядке** (`127-i`).
Это позволяет второй головке, установленной зеркально, выдавать угол в той же системе отсчёта.
Та же переменная используется как номер слота случайной задержки SPI.

Цикл развёрнут с шагом 2 — ручная оптимизация, функция вызывается ~9900 раз в секунду.

### 6.2 `find_startpixel()` — поиск репера

Строит корреляцию кадра с бинарным шаблоном, **продублированным** со сдвигом `+SECTOR_SIZE`:

```c
scor[i] = (max_data - buf_x1[i+0]) + ... + (max_data - buf_x1[i+9])   // 10 тёмных
        + (buf_x1[i+10] - min_data) + ... + (buf_x1[i+12] - min_data) // 3 светлых = РЕПЕР
        + (max_data - buf_x1[i+14]) + ... + (max_data - buf_x1[i+18]) // 5 тёмных
        + /* то же самое со сдвигом +51 */;
```

Поиск **пары** реперов вместо одного резко снижает вероятность ложного срабатывания
на случайном сочетании битов кода.

Выбор среди двух лучших кандидатов идёт не по величине `scor`, а по **остроте пика**:

```c
scor_max1 = (scor[max1_pos]-scor[max1_pos-1]) + (scor[max1_pos]-scor[max1_pos+1]) + scor[max1_pos];
```

Настоящий репер даёт узкий пик, ложный — размытый.

### 6.3 `mes_piks()` + `BR4_C()` — субпиксельная координата

Целого номера пикселя мало: 1 пиксель = 176 угловых секунд. Поэтому:

1. в окне `[star_pixel+4, star_pixel+16)` формируется `buf_x2[i] = buf_x1[i] * buf_k[i]`;
2. находится индекс максимума `max_X0`;
3. `BR4_C(buf_x2, max_X0)` возвращает дробную координату центра пятна.

Математика `BR4_C` — в [математическом документе, §3](angle_math_and_calibration.md#3-субпиксельная-оценка-координаты-репера-br4_c).

### 6.4 `find_datablock()` — выборка битов

Опорная сетка строится **от измеренных реперов**, а не от номинала:

```c
sec_size = s_l2 - s_l1;                   // фактическая ширина сектора, пиксели
pix_size = sec_size / BITS_PER_SECTOR;    // ширина одной битовой ячейки
right_f  = s_l1 + pix_size*3;             // центр первого бита
```

Благодаря этому сетка автоматически подстраивается под изменение расстояния до диска,
температурное расширение и перекос установки.

Уровни «белого»/«чёрного» (`max_sdata`, `min_sdata`) берутся **локально**,
по области `[startpixel1+14, startpixel1+51)`, — порог решения устойчив к неравномерности подсветки.

Яркость в центре бита вычисляется **линейной интерполяцией** (`get_pix()`), т.к. центры
битовых ячеек почти никогда не попадают на целый пиксель.

### 6.5 `calc_sector()` — декодирование

Три действия:

1. **Мягкое решение**: ищется бит с минимальным `|pix[i][1] - pix[i][0]|` — отсчёт, ближе
   всего лежащий к середине между чёрным и белым. Его индекс → `badbit_pos`, запас → `badbit_value`.
2. **Сборка кода**: `бит = 1, если pix[i][1] > pix[i][0]`, упаковка старшим вперёд с маски `0x100`.
3. **Поиск в `bit_tab[]`**: `rem_sec` = индекс или **255**, если кода нет в таблице.

> ✅ **Исправленный дефект.** В исходной версии цикл поиска ненадёжного бита шёл
> `for (int i=0; i<11; i++)` при массиве `int16_t pix[9][2]` (чтение **за границей массива**,
> неопределённое поведение), а в `bit_err_corr()` маски начинались с `0x400` (11 бит) вместо
> `0x100` (9 бит) — наследие 11-битного варианта кода. Сейчас граница цикла равна `9`, а маска
> разряда — `0x100 >> badbit_pos`. Полный перебор 1296 однобитовых ошибок: было исправлено
> **11,1 %**, стало **100 %**. Разбор, цифры и регрессионный тест — в
> [математическом документе, §5.3](angle_math_and_calibration.md#53-два-дефекта-декодирования-и-их-исправление).

### 6.6 `err_corr()` — контроль и коррекция

Трёхуровневая схема (подробный разбор — в математическом документе):

| Фаза | Условие | Действие |
|---|---|---|
| «Прогрев» | `sec_cnt < 50` | любой номер принимается на веру |
| Норма | `rem_sec ∈ {lsec, cursec, rsec}` | `save_sector()` |
| Ошибка, попытка 1 | `rem_sec == 255` или вне окна | `serrcnt2++`, `bit_err_corr()` — инверсия худшего бита |
| Ошибка, попытка 2 | и после коррекции вне окна | `serrcnt1++`, `errorflag = 1`, окно всё равно переустанавливается |

Переустановка окна даже при неисправимой ошибке — важная деталь: иначе головка
«залипнет» навсегда после реального механического проскока.

### 6.7 `calc_ang()` — угол

```c
ts_l2     = -(s_l1 - offset);               // смещение точки съёма от левой границы
ts_l1     = -(s_l2 - offset);               // то же от правой границы
pix_dif   = ts_l2 - ts_l1;                  // = s_l2 - s_l1, ширина сектора в пикселях
r_angle   = ang_tab[rsector];
l_angle   = ang_tab[sector];
angle_dif = r_angle - l_angle;  if (angle_dif < 0) angle_dif += 360;
k_pix     = angle_dif / pix_dif;            // масштаб град/пиксель — СВОЙ для каждого сектора
t_l1      = l_angle + ts_l2 * k_pix;
t_l       = 360 - t_l1;                     // разворот направления отсчёта
cur_ang   = приведение t_l к [0, 360);
```

Ключ: **`k_pix` берётся не из номинала `2.5/51`**, а из реальной ширины конкретного сектора
и реальных углов его границ из калибровочной таблицы `ang_tab`.

## 7. Семейство субпиксельных алгоритмов

В файле реализованы **десять** оценок центра светового пятна. Фактически вызывается **одна**:

| Функция | Метод | Вызывается? |
|---|---|---|
| **`BR4_C`** | 4-точечная балансная оценка + компенсация S-образной ошибки | **да**, из `mes_piks()` |
| `BR4` | то же без компенсации | нет |
| `BR4_F`, `BR6_F` | то же с предварительной КИХ-фильтрацией (`filt_a/b/c`) | нет |
| `BR6`, `BR8` | балансные оценки на 6 и 8 отсчётах | нет |
| `calc` | метод половины интеграла (медиана профиля) | нет |
| `INTEGRAL` | полиномиальная коррекция интегральных отношений | нет |
| `KVADRATURA` | центр масс по квадратам отсчётов | нет |
| `CENTR_OF_MASS` | классический центр масс | нет |
| `Fast2ArcTan` | полиномиальный `arctan` | нет |

Невызываемые варианты оставлены как экспериментальный материал для сравнения точности.
Там же — `startpixel_err_corr()`: заготовка второго уровня коррекции (перевыбор репера),
**нигде не вызывается**.

## 8. Блок самокалибровок

Три независимые процедуры, каждая — **конечный автомат**, продвигающийся по одному шагу
за кадр и управляемый по SPI. Полный разбор (математика, условия входа, контроль хода) —
в [математическом документе, §8–§11](angle_math_and_calibration.md#8-общая-схема-самокалибровки).

| Функция | Что калибрует | Команда | Результат в EEPROM |
|---|---|---|---|
| `angk_cal()` | `buf_k[128]` — неравномерность чувствительности пикселей | `0x14` | стр. 3, адрес 768, 512 Б + CRC16 |
| `offset_cal()` | `offset` — точка съёма угла на линейке | `0x13` | стр. 6, адрес 1536, 4 Б + CRC16 |
| `angtab_cal()` | `ang_tab[144]` — **таблица углов секторов** | `0x11`, затем `0x12` | стр. 0, адрес 0, 576 Б + CRC16 |

Общая метрика качества для `offset_cal()` и `angk_cal()` — переменная **`min_max`**,
которую вычисляет `find_avg()`: размах остаточной ошибки угла за оборот.
`angtab_cal()` метрику не использует — он работает по **принципу замыкания окружности**.

## 9. `find_avg()` — метрика качества измерения

Абсолютного эталона угла в системе нет, поэтому критерием служит **гладкость** выходного
сигнала при равномерном вращении:

```c
avg_buf[0] = cur_ang_X;                      // сдвиговый буфер на 30 кадров (~3 мс)
avg_ang_X  = (1/30) * Σ avg_buf[i];          // среднее по окну
avg_cur    = avg_ang_X - avg_buf[15];        // остаток в ЦЕНТРЕ окна
```

При постоянной скорости истинный угол линеен по времени, а среднее линейной функции по
симметричному окну равно её значению в центре. Значит `avg_cur` — это **ошибка измерения,
очищенная от самого движения** (фактически ФВЧ-фильтр).

За оборот накапливаются экстремумы `cur_min` / `cur_max`; переход через 0/360°
детектируется по условию «свежий отсчёт < 0.5° и самый старый > 359.5°» (и наоборот) —
это же даёт счётчики оборотов `rev_right_cnt` / `rev_left_cnt` и инкремент `avg_minmax_num`.
Экстремумы усредняются по `offset_avg_num = 3` оборотам, и получается

```c
min_max = avg_max - avg_min;   // ЦЕЛЕВАЯ ФУНКЦИЯ оптимизации
```

## 10. Управление фотолинейкой (жёсткое реальное время)

Три аппаратных блока работают согласованно:

| Блок | Роль |
|---|---|
| **TIM3 CH1 → PC6** | генератор **T-CLK**: `Period = 32`, APB1-таймеры 108 МГц, режим `TIM_OCMODE_TOGGLE` → частота обновления 108/33 = 3.27 МГц, на выводе — меандр **1.636 МГц** |
| **EXTI11 ← PB11** | тот же T-CLK заведён обратно в МК и **аппаратно** триггерит `ADC2` по спаду |
| **DMA2 Stream3** | 132 полуслова на кадр, кольцевой режим + double buffer, прерывание по Transfer Complete, приоритет NVIC **0** |

### `DMA2_Stream3_IRQHandler()` — сердце системы

```c
KIN1_ResetCycleCounter(); KIN1_EnableCycleCounter();   // старт профилирования
__disable_irq();
SCB_InvalidateDCache_by_Addr(ADC_VAL ...);             // DMA писал мимо кэша
while (!LL_GPIO_IsInputPinSet(GPIOC, LL_GPIO_PIN_6)) {} // ловим фронт T-CLK
while ( LL_GPIO_IsInputPinSet(GPIOC, LL_GPIO_PIN_6)) {} // и спад
LL_TIM_DisableCounter(TIM3);                           // остановить такты
DelayTim4Ticks(TSL1401_TQT_TIM_TICKS);                 // выдержка tqt = 20 мкс
LL_GPIO_SetOutputPin(GPIOA/C, SI);                     // SI = 1  -> старт нового кадра
Backlight_StartFromSI();                               // запуск одновибратора подсветки
LL_TIM_EnableCounter(TIM3);                            // такты снова пошли
while (!LL_GPIO_IsInputPinSet(GPIOC, LL_GPIO_PIN_6)) {}
LL_GPIO_ResetOutputPin(GPIOC, LL_GPIO_PIN_7);          // SI = 0
/* выбор "неактивного" буфера double buffer и копирование 128 пикселей в buf_x0 */
if (adc_rdy == 0) { memcpy(buf_x0, adc_addr, 256); adc_rdy = 1; }
__enable_irq();
```

Два момента, которые легко упустить:

* **`if (adc_rdy == 0)`** — если предыдущий кадр ещё не обработан, новый просто **отбрасывается**.
  Система не копит задержку: лучше пропустить кадр, чем выдать устаревший угол.
* Ожидание фронтов `PC6` — **активный опрос** внутри прерывания с запрещёнными прерываниями.
  Это сознательный выбор: 20 мкс жёсткой выдержки дешевле организовать опросом, чем планировщиком.

### Подсветка: `TIM4` как одновибратор

```
SI ──┐
     └─ backlight_delay_ticks (1220 тиков ≈ 11.3 мкс) ─┐
                                                       └─ PA15 = 1
                                                          backlight_width_ticks (2500 ≈ 23 мкс)
                                                          └─ PA15 = 0
```

Автомат `backlight_timer_state`: `IDLE → DELAY → WIDTH → IDLE`, переходы в `TIM4_IRQHandler()`.
Привязка вспышки к SI делает экспозицию одинаковой для всех пикселей кадра.

### `dac_ctrl()` — АРУ подсветки

Медленный интегральный регулятор: **±1 тик за 1000 кадров** (≈ 10 раз в секунду):

```c
avg_max_data = Σ max_data / 1000;
if (avg_max_data < max_level_pix - 200)  backlight_width_ticks++;   // темно
else if (avg_max_data > max_level_pix)   backlight_width_ticks--;   // светло
adc_offset = avg_max_data / 5;                                      // подстройка пьедестала
```

Пределы `2 … 9400` тиков (≈ 0.02 … 87 мкс). Медленность намеренная: регулятор не должен
реагировать на смену сектора, только на загрязнение оптики, старение светодиода и температуру.
Флаг `backlight_width_en = 0` **запрещает** АРУ — это делает команда `0x14`
на время калибровки `buf_k`, иначе пиковый детектор мерил бы «плавающую» яркость.

## 11. Протокол SPI (связь с внешним контроллером)

### Физика

| Параметр | Значение |
|---|---|
| Интерфейс | `SPI2`, выводы `PB12` (NSS, программный), `PB13` (SCK), `PB14` (MISO), `PB15` (MOSI) |
| Режим | 16 бит, CPOL=0, CPHA=2EDGE, MSB first |
| Скорость | APB1 54 МГц / 8 = **6.75 МГц** |
| Роль STM32 | **мастер** — головка сама инициирует кадр |
| Передача | DMA1 Stream4 (TX) и Stream3 (RX), приоритеты NVIC 7 и 6 |

### Структура кадра (10 полуслов = 20 байт)

```
полуслово [0]     : 0x55 (преамбула) | младший байт счётчика кадров
полуслово [1..7]  : 14 байт полезной нагрузки
                      байт 0      = код команды/ответа
                      байт 1      = encoder_state     <- КОД СОСТОЯНИЯ ГОЛОВКИ
                      байты 2..5  = cur_ang_E, IEEE-754 float, угол в градусах
                      байты 6..13 = данные конкретной команды
полуслово [8..9]  : CRC32 по первым 16 байтам (аппаратный блок CRC)
```

**`encoder_state` и `cur_ang_E` подставляются в ЛЮБОЙ исходящий кадр** (`spi_SendExec()`),
независимо от того, какая команда обрабатывается. Поэтому мастеру достаточно слушать поток
кадров, чтобы одновременно получать угол и следить за ходом калибровки.

### Разрешение коллизий (две головки на одной шине)

```c
rng_value = HAL_RNG_GetRandomNumber(&RNG_Handle) & 0x0FFF;
LL_TIM_SetCounter(TIM2, 10 + (1000 + rng_value) * config_state);
LL_TIM_EnableCounter(TIM2);    // старт DMA произойдёт в TIM2_IRQHandler
```

* головка с `config_state == 0` выходит на шину почти сразу (задержка 10 тиков);
* головка с `config_state == 1` ждёт `1000 + случайное(0…4095)` тиков — случайный слот.

`TIM5` даёт паузу 1000 тиков после окончания передачи, прежде чем снять NSS.

### Контроль целостности (`Recv_SPI()`)

Две независимые проверки:

1. **CRC32** (аппаратная). Не сошлась → `spi_badframes++` и **полная переинициализация SPI2**
   (`MX_SPI2_Init()`) — типовой приём восстановления после побитовой рассинхронизации.
2. **Счётчик кадров**. Не равен ожидаемому → `spi_lostframes++`, кадр не обрабатывается.

> Блок **CRC один на весь МК** и имеет внутреннее состояние, поэтому расчёт в `Send_SPI()`
> и `Recv_SPI()` обрамлён `__disable_irq()` / `__enable_irq()`.

### Таблица команд

| Код | Имя | Обработка |
|---|---|---|
| `0x25` | `spi_ReadStatus` | телеметрия (отправляется, когда очереди пусты) |
| `0x61` | `spi_ReadBadFrames` | счётчик `spi_badframes` |
| `0x62` | `spi_ReadTemperature` | температура кристалла (`float`) |
| `0x71…0x76` | `spi_Prog*` | загрузка и проверка образа прошивки |
| `0x79` | `spi_ProgGetVersion` | `update_version` (= 11) и `prog_errcode` |
| `0x7a` | `spi_ProgExecBoot` | перезапуск в загрузчик через WWDG |
| **`0x10`** | — | **СТОП всех калибровок**, `encoder_state = 0x00` |
| **`0x11`** | — | старт прохода 1 калибровки `ang_tab`, `encoder_state = 0x10` |
| **`0x12`** | — | старт прохода 2 калибровки `ang_tab`, `encoder_state = 0x30` |
| **`0x13`** | — | старт калибровки `offset`, `encoder_state = 0x50` |
| **`0x14`** | — | старт калибровки `buf_k`, `encoder_state = 0x70` |

**Быстрые** команды обрабатываются прямо в `spi_recv_process()`.
**Медленные** (стирание/запись внешней Flash, CRC32 по всему образу — десятки миллисекунд)
только взводят флаг `SloCom`, а выполняются в `SloComProcess()` из главного цикла,
иначе сорвалось бы реальное время кадра.

## 12. Обновление прошивки

Схема двухступенчатая (типовая для промышленных устройств):

```
Мастер --SPI2--> STM32 --SPI1--> внешняя Flash AT25SF641 (образ)
                                        |
                              загрузчик (0x08000000..0x0800FFFF)
                                        v
                          внутренняя Flash МК (0x08010000+)
```

| Функция | Назначение | Коды ошибок |
|---|---|---|
| `ProgBlock()` | запись блока 4 КБ: CRC16 → Write Enable → стирание 4 КБ → страницы по 256 Б → обратное чтение и сравнение | 0 OK, 1 CRC16, 2 Flash |
| `CalcUpdateChecksum()` | CRC32 по всему образу во внешней Flash | 0 OK, 3 CRC32 |
| `ProgFlashHeader()` | запись заголовка (длина, CRC32, время) | 0 OK, 4 Flash |
| `ProgCheckStm32()` | сверка внутренней Flash с образом | 0 OK, 100 CRC32, 101 несовпадение |
| `Flash_Read_Data()` | чтение внутренней Flash (она отображена в адресное пространство) | — |

Переход в загрузчик (`spi_ProgExecBoot`) сделан красиво: в EEPROM пишется признак
`boot_state = 0`, затем **включается WWDG и намеренно не обслуживается** — через ~2 с
происходит аппаратный сброс, и загрузчик видит признак обновления.

## 13. Инициализация: `init_vars()` и `main()`

### `init_vars()`

1. Очистка очередей SPI (`spi_FreeAll()`).
2. **Одно блокирующее чтение** всей EEPROM (2048 байт) в `eeprom_buf[]`.
3. Для каждого из четырёх блоков (`ang_tab`, `buf_k`, `offset`, `lasdac`):
   пересчёт **CRC16** и сравнение с хранимой суммой.
   * сошлась → копировать в рабочую переменную, поднять флаг `*_rdy = 1`;
   * не сошлась → **молча игнорировать**, остаётся значение по умолчанию из кода.
4. Чтение перемычки `PB8` → `config_state`.
5. `ProgCheckStm32()` — сверка прошивки, результат в `prog_errcode`.
6. Заполнение `delta_cor[200]` — табулированная синусоида компенсации
   (используется только невызываемыми `BR6`/`BR8`).

> Флаги `ang_tab_rdy`, `buf_k_rdy`, `offset_rdy` выставляются, но **нигде не проверяются** —
> при повреждённой EEPROM устройство тихо работает на значениях «из прошивки».

### `main()`

Архитектура — **суперцикл без ОС**:

* прерывания выполняют только жёсткое реальное время (тактирование линейки,
  перекладывание кадра, приём/передача SPI);
* вся арифметика — в `while(1)` по флагу `adc_rdy`.

Порядок инициализации:

```c
HAL_Init();                 // сброс периферии, Flash interface, SysTick
SystemClock_Config();       // HSE 25 МГц -> PLL -> SYSCLK 216 МГц
SCB_EnableICache();         // кэш инструкций
SCB_EnableDCache();         // кэш данных -> ОТСЮДА нужны ручные операции с кэшем при DMA
MX_GPIO_Init(); MX_DAC_Init(); MX_ADC1_Init(); MX_ADC2_Init();
MX_TIM3_Init(); MX_TIM4_Init(); MX_SPI2_Init(); MX_SPI1_Init();
MX_CRC_Init(); MX_RNG_Init(); MX_I2C3_Init();
init_vars();                // калибровки из EEPROM
KIN1_InitCycleCounter(); KIN1_EnableCycleCounter();
__enable_irq();
```

### `SystemClock_Config()`

```
HSE 25 МГц → /M=25 → 1 МГц → ×N=432 → 432 МГц → /P=2 → SYSCLK = 216 МГц
AHB  /1 = 216 МГц
APB1 /4 =  54 МГц  → таймеры APB1 = 108 МГц   (TIM2, TIM3, TIM4, TIM5)
APB2 /2 = 108 МГц  → таймеры APB2 = 216 МГц
```

На 216 МГц обязательны **7 тактов задержки Flash** (`LL_FLASH_LATENCY_7`),
режим питания **Scale 1** и **Over-drive** — иначе ядро не стартует стабильно.

| `PC4` | `SPI1` NSS — внешняя Flash | `MX_SPI1_Init()` |
| `PC6` | `TIM3_CH1` — **T-CLK** фотолинейки | `MX_TIM3_Init()` |
| `PC7` | **T-SI** — импульс старта кадра | `MX_GPIO_Init()` |
| `PC9` (I2C3_SDA), `PA8` (I2C3_SCL) | EEPROM | `HAL_I2C_MspInit()` |

## 16. Замечания и риски, найденные при разборе кода

1. ✅ **Исправлено.** Выход за границу массива в `calc_sector()` (`i<11` при `pix[9][2]`) и
   несогласованные маски в `bit_err_corr()` (`0x400` вместо `0x100`). Коррекция однобитовых
   ошибок выросла с 11,1 % до 100 % (полный перебор 144 сектора × 9 бит). Защищено
   регрессионным тестом `tests/sector_decode_test.py`; разбор — в
   [математическом документе, §5.3](angle_math_and_calibration.md#53-два-дефекта-декодирования-и-их-исправление).
2. **`startpixel_err_corr()` не вызывается** — второй уровень коррекции (перевыбор репера) выключен.
3. **Флаги `*_rdy` не проверяются** — при битой EEPROM устройство работает на умолчаниях без сигнализации.
4. **Запись больших блоков в EEPROM одной транзакцией.**
   `HAL_I2C_Mem_Write_IT(..., EEPROM_DEVICE_PAGE0, 0, ..., 578)` пишет 578 байт за один раз.
   У классических I2C-EEPROM объёмом 16 Кбит размер страницы записи — 16 байт, и запись
   длиннее страницы **заворачивается внутри страницы**. Аналогично чтение всех 2048 байт одной
   транзакцией опирается на сквозную автоинкрементацию адреса через границы 256-байтных блоков.
   **Требует проверки по даташиту конкретной установленной микросхемы** (в репозитории её
   обозначения нет). Если это обычный 24Cxx — запись калибровок будет некорректной.
5. **Нет таймаута на активный опрос** `while (!LL_GPIO_IsInputPinSet(GPIOC, LL_GPIO_PIN_6)) {}`
   в обработчике кадра: при пропадании T-CLK (обрыв, отказ TIM3) МК зависнет в прерывании
   с запрещёнными прерываниями. WWDG в рабочем режиме не включён.
6. **Проверка непрерывности сектора ограничивает скорость**: не более одного сектора за кадр,
   т.е. ≈ 24800 °/с ≈ 4100 об/мин. Выше — лавина `serrcnt1`.
7. `Error_Handler()` **пустой** — отказ инициализации периферии ничем не сигнализируется.
8. Четвёртый «слабый» пиксель `pix_min4_num` в `angk_cal()` находится, но **не используется**
   (`case 8` сразу переходит к `anglek_phase = 100`).
9. **Кодировка исходников — CP1251** (см. `.gitattributes`, `working-tree-encoding=CP1251`).
   Часть старых комментариев уже потеряна и выглядит как `?????` — это следы конвертации
   в однобайтовую кодировку без поддержки кириллицы.
