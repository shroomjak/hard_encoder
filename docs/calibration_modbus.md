# Самокалибровка головки по Modbus RTU — процедура оператора

Запуск самокалибровки адресной записью в одну головку на шине RS-485. Коды команд
те же, что исторически приходили по SPI (`0x10…0x14`); конечные автоматы в
`Src/main.c` не изменены — запись только взводит флаги запуска, которые ставит
отладчик. Реализация: `Inc/modbus_calib.h`, `Src/modbus_calib.c`,
`Src/modbus_registers.c`. Утилита: `tools/modbus_calib.py`.

Содержание: [§1 подготовка](#1-что-подготовить) · [§2 регистры](#2-регистры) ·
[§3 порядок](#3-порядок-калибровки) · [§4 приёмка](#4-приёмка-результата) ·
[§5 ошибки](#5-неудача-и-повтор) · [§6 готовые кадры](#6-готовые-кадры)

## 1. Что подготовить

| Условие | Требование |
|---|---|
| Вал | равномерное вращение от привода. Вращать рукой нельзя: все автоматы считают статистику по **полным оборотам** |
| Скорость `0x14`, `0x13` | **10…40 об/мин**. Жёсткий предел 57 об/мин: выше переход угла через 0°/360° не детектируется и счётчик оборотов стоит |
| Скорость `0x11`, `0x12` | **5…20 об/мин**. Отсчёт ширины сектора берётся в узком стробе (около 1 пикселя), на высокой скорости сектора пропускаются и `RDY1`/`RDY2` растут медленно |
| Угол уже считается | переходы через 0°/360° ищутся по текущему углу, поэтому до первой калибровки нужна хотя бы штатная таблица `ang_tab` (в прошивке есть начальная, при пустом EEPROM угол считается по ней) |
| Направление | для `0x11` угол должен расти, для `0x12` — убывать. Проверяется по регистрам 23 и 24 (§2.2) |
| Линия | RS-485, 115200 8E1, один ведущий |
| Адрес головки | 1…247, задаётся при сборке прошивки (`MB_SLAVE_ADDRESS`). В утилите — ключ `-s`/`--slave` (например `-s 2 status`); адрес неизвестен — `python3 tools/modbus_calib.py scan` переберёт линию и покажет ответившие |
| Вещание | адрес 0 не использовать: команду выполнят все головки сразу, ответа не пришлёт ни одна |
| Головка | работает штатно, угол считается (регистры 26…27 меняются), ошибок шины нет |
| Копия таблиц | `ang_tab` до перезаписи (§3, шаг 2). Без неё не к чему вернуться |
| Утилита | `python3 tools/modbus_calib.py`, нужна pyserial; без неё — любой Modbus-терминал и кадры из §6 |

## 2. Регистры

Адреса — **на проводе**, с нуля. Запись — только FC06, по одному регистру
(FC16 и FC03 в сборке выключены). Чтение — FC04. Всего входных регистров 63.

### 2.1 Запись, FC06

| Адрес | 4x | Имя | Значение |
|---|---|---|---|
| 0 | 400001 | `SNAP` | любое — зафиксировать снимок кадра (относится к §[modbus_rtu.md](modbus_rtu.md), к калибровке отношения не имеет) |
| 1 | 400002 | `CAL_CMD` | код команды: `0x10`…`0x14` |
| 2 | 400003 | `CAL_PAGE` | окно выгрузки: `[15:8]` — номер таблицы (`0` — `ang_tab`, `1` — `buf_k`), `[7:0]` — индекс первого элемента |

Коды `CAL_CMD`:

| Код | Действие | Сразу после записи STATE= | STATE=, когда готово |
|---|---|---|---|
| `0x14` | `angk_cal` — коэффициенты `buf_k[128]` | `0x70` | `0x80` |
| `0x13` | `offset_cal` — точка съёма `offset` | `0x50` | `0x60` |
| `0x11` | `angtab_cal`, проход 1 — вал «вправо», угол растёт | `0x10` | `0x20` |
| `0x12` | `angtab_cal`, проход 2 — вал «влево», угол убывает | `0x30` | `0x40` |
| `0x10` | стоп: снять все флаги запуска, включить АРУ подсветки | `0x00` | — |

Нумерация кодов унаследована от SPI-протокола: у каждой команды своя пара кодов
состояния (`0x11` → `0x10`/`0x20`, `0x12` → `0x30`/`0x40`, `0x13` → `0x50`/`0x60`,
`0x14` → `0x70`/`0x80`). Порядок запуска — обратный нумерации (`0x14`, `0x13`,
`0x11`, `0x12`, §3): он задан тем, что от чего зависит, а не номерами.

Неизвестный адрес регистра → исключение `0x02`, неизвестный код команды или номер
таблицы → `0x04`. Других записей нет: ни `CAL_PAGE`, ни `CAL_CMD` обратно не
читаются — состояние видно только в блоке §2.2.

### 2.2 Чтение, FC04: живой блок 11…30

Всегда актуален на момент запроса (снимок 0…10 обновляется только по `SNAP`).
Полный опрос: FC04, адрес 11, количество 20.

| Адрес | Имя | Что там |
|---|---|---|
| 11 | `STATE` | код этапа (таблица в §2.1) |
| 12 | `RDY1` | прогресс прохода 1 `ang_tab`, 0…144 секторов |
| 13 | `RDY2` | прогресс прохода 2 `ang_tab`, 0…144 |
| 14 | `OFFSET_PHASE` | фаза `offset_cal`: 0…5 — перебор, 100 — запись в EEPROM, 101 — кончено |
| 15 | `OFFSET_CUR` | текущая проверяемая позиция `offset` |
| 16 | `OFFSET_FOUND` | позиция, принятая по итогам перебора |
| 17 | `OFFSET_X256` | `offset` × 256, пиксели (например 17536 = 68,5 пикс.) |
| 18 | `ANGK_PHASE` | фаза `angk_cal`: 1…8 — перебор, 100 — запись, 101 — кончено |
| 19 | `PIX_MIN_MAX` | разброс пиков по линейке, отсчёты АЦП, знаковый. Цель — ниже 100 |
| 20…21 | `MINMAX` | `min_max` — метрика качества, знаковые микроградусы (утилита печатает в угловых секундах) |
| 22 | `REVS` | сколько оборотов учтено в текущей пробе |
| 23 | `REV_RIGHT` | оборотов «вправо» с начала работы |
| 24 | `REV_LEFT` | оборотов «влево» с начала работы |
| 25 | `SERR1` | кадров с неисправимой ошибкой декодирования |
| 26…27 | `ANGLE` | текущий угол `cur_ang_E`, микроградусы |
| 28…29 | `FRAMES` | обработано кадров АЦП (`uint32`) |
| 30 | `EEPROM` | бит 0 — записей в EEPROM не осталось; бит 1 — `ang_tab` принята; бит 2 — `buf_k`; бит 3 — `offset` |

32-битные поля — два регистра, старшее слово первым. `PIX_MIN_MAX` и `MINMAX`
знаковые.

### 2.3 Окно выгрузки таблиц: 31…62

16 значений `float` = 32 регистра (IEEE-754, старшее слово первым). Как читать:
записать в `CAL_PAGE` номер таблицы и индекс первого элемента, затем прочитать
FC04, адрес 31, количество 32. Индекс прижимается к концу таблицы, за границу
выйти нельзя. `ang_tab` — 144 значения (9 страниц: индексы 0, 16, 32 … 128),
`buf_k` — 128 (8 страниц: 0, 16 … 112).

## 3. Порядок калибровки

Команды идут в порядке **`0x14` → `0x13` → `0x11` → `0x12` → `0x10`**. Порядок
задан зависимостями в `Src/main.c`:

* `angtab_cal()` (`0x11`, `0x12`) измеряет ширину сектора в пикселях и берёт её
  только в момент, когда репер сектора стоит ровно в полусекторе от точки съёма:
  `s_l1` в окне `offset-25 … offset-24` (или `s_l2` в `offset+24 … offset+25`).
  Значит нужен готовый `offset`, и нужны чистые границы `s_l1`, `s_l2`, которые
  считаются после поправочных коэффициентов → `0x14` и `0x13` раньше.
* `offset_cal()` (`0x13`) и угловая часть `angk_cal()` (`0x14`, фазы 4, 6 и 8)
  минимизируют `min_max` — размах остатка угла. Остаток считается по текущему углу,
  а угол — по **текущей** `ang_tab`. То есть связь двусторонняя: эти две калибровки
  дают `ang_tab` нужную геометрию (точку съёма и ровные границы), но верную оценку
  качества получают только по уже выправленной шкале. Поэтому один круг — это
  `0x14`, `0x13`, `0x11`, `0x12`, а дальше `0x14` и `0x13` повторяют (шаг 9).

Между шагами ждать нужного `STATE`.

Ориентир по длительности — в **оборотах**, потому что все автоматы продвигаются по
счётчику полных оборотов (`REVS`, регистр 22) и в минутах зависят от скорости:
`0x14` — 50…70, `0x13` — 12…68 (по 4 оборота на пробу, проб от 3 до 17), каждый
проход `ang_tab` — 5…10 (по 5 отсчётов ширины на сектор).

1. **Проверить исходные данные.** FC04, адрес 11, количество 20. Должно быть:
   `STATE = 0x00`, `FRAMES` растёт, `ANGLE` меняется при вращении. Биты 1…3
   регистра `EEPROM` равны 1, если таблицы уже приняты; при пустом или битом
   EEPROM они нулевые — это не помеха, угол считается по начальной таблице
   прошивки. Привод включён.

2. **Сохранить `ang_tab`.** Страницы 0…128: `CAL_PAGE := 0x0000`, затем FC04
   адрес 31, количество 32; далее `CAL_PAGE := 0x0010`, `0x0020`, … В утилите
   одним делом:

   ```sh
   python3 tools/modbus_calib.py dump -s <адрес> --table ang_tab --csv ang_tab_before.csv
   ```

   `buf_k` и `offset` сохранять полезно, но не обязательно: `buf_k` —
   `--table buf_k`, `offset` виден в регистре 17.

3. **Запустить `buf_k`:** `CAL_CMD := 0x14`, обороты 10…40. Фазы 1 и 2
   выравнивают яркость пикселей и заканчиваются, когда `PIX_MIN_MAX` (регистр 19)
   станет меньше 100 отсчётов АЦП; фазы 3…8 подбирают коэффициент для трёх самых
   слабых пикселей по `MINMAX`. Идёт 50…70 оборотов. Окончание — `STATE = 0x80`,
   `ANGK_PHASE = 101`, затем бит 0 в `EEPROM` возвращается в 1. АРУ подсветки
   включится сама.

4. **Запустить `offset`:** `CAL_CMD := 0x13`, обороты 10…40. Ждать:
   `STATE = 0x50`, `OFFSET_PHASE` идёт 1…5, `REVS` — плюс 4 оборота на каждую
   пробу. Окно перебора — 63…65 пикселей, при минимуме на краю расширяется до
   56…72, то есть проб от 3 до 17 и оборотов от 12 до 68. Окончание — `STATE = 0x60`,
   `OFFSET_PHASE = 101`, `OFFSET_FOUND` = принятая позиция, `MINMAX` по модулю
   меньше, чем было. Затем `EEPROM` бит 0 = 1.

5. **Проверить направление.** Перед `0x11` должен расти `REV_RIGHT`, перед `0x12`
   — `REV_LEFT`. Если не так — остановить привод, сменить направление, повторить
   команду прохода.

6. **Проход 1 таблицы углов:** `CAL_CMD := 0x11`, обороты **5…20**. Угол должен
   **расти**. `RDY1` считает готовые сектора 0…144 (по 5 отсчётов на сектор).
   Окончание — `STATE = 0x20`, `RDY1 = 144`. Калибровка в этот момент
   **не записана**: нужен второй проход.

7. **Проход 2:** `CAL_CMD := 0x12`, обороты **5…20**. Угол должен **убывать**.
   Окончание —
   `STATE = 0x40`, `RDY2 = 144`, затем `ang_tab` уходит в EEPROM (биты 0 и 1 в
   `EEPROM` = 1).

8. **Остановить:** `CAL_CMD := 0x10`. `STATE = 0x00`, флаги запуска сняты,
   АРУ подсветки включена. Останов нужен, чтобы головка вернулась в штатный
   режим; результат калибровки он не отменяет.

9. **Повторить `0x14`, затем `0x13`** (оба — 10…40 об/мин, шаги 3 и 4). После
   записи новой `ang_tab` метрика `MINMAX` считается по выправленной шкале, и
   обе калибровки получают правильную целевую функцию. Признак того, что второй
   круг нужен: `MINMAX` после шага 7 стал больше, чем до него, или `PIX_MIN_MAX`
   вышел за 100. Если после второго круга `MINMAX` уже не улучшается —
   дальнейшие повторы бесполезны.

10. **Проверить после перезагрузки** (снять питание, подать): `EEPROM` = 15, а
   `ANGLE` при том же положении вала совпадает с углом до перезагрузки. Это
   подтверждает, что блоки в EEPROM читаются с верной CRC16.

11. **Сравнить таблицы и качество:**

    ```sh
    python3 tools/modbus_calib.py dump -s <адрес> --table ang_tab --csv ang_tab_after.csv
    python3 tools/modbus_calib.py diff ang_tab_before.csv ang_tab_after.csv
    ```

    И повторить эксперимент с валом (§4).

Проще делать шаги 3…9 утилитой: `python3 tools/modbus_calib.py run -s <адрес>
--port /dev/ttyUSB0` — она отправляет команды в нужном порядке, ждёт `STATE` и
при `Ctrl-C` посылает `0x10`.

## 4. Приёмка результата

Сравнить до и после на том же стенде (эксперимент 4 в README):

| Признак | Как проверить | Годится |
|---|---|---|
| Разброс пиков | `PIX_MIN_MAX` (регистр 19) | < 100 отсчётов АЦП |
| Точность | `MINMAX` (регистры 20…21), диагностические графики | модуль уменьшился |
| Срывы счёта | `SERR1` (регистр 25) на чистом диске | не растёт |
| Непрерывность угла | `ANGLE` при равномерном вращении | скачков на величину шага сектора нет |
| Таблица изменена | `diff` выгрузок | значения отличаются, порядок величин сохранён |

## 5. Неудача и повтор

Защиты от повторного запуска нет, и отката тоже. Прерванный или неудачный этап
просто повторяют: незаписанный результат при перезагрузке вернётся из EEPROM, так
что головка не остаётся с «полтаблицы».

| Что видно | Что делать |
|---|---|
| Прогресс стоит: `REVS` (регистр 22) не растёт или `ANGK_PHASE`/`OFFSET_PHASE` не менялись за 20 оборотов | `CAL_CMD := 0x10`; проверить, что вал вращается ровно (`FRAMES` и `ANGLE` движутся), что угол проходит через 0°/360° и что скорость в пределах для этой команды (§1); повторить команду |
| `PIX_MIN_MAX` не опускается ниже 100 | фаза 2 `angk_cal` ходит по кругу: оптика грязная или блики, либо `backlight_width_ticks` у пределов 2 и 9400. Протереть оптику, затем повторить `0x14` |
| `RDY1`/`RDY2` стоят на месте | угол не проходит через секторы: проверить диск, загрязнение, АРУ подсветки (`0x10` её возвращает) |
| Исключение `0x02` | записали не в `CAL_CMD` (адрес 1) — см. §2.1 |
| Исключение `0x04` | не тот код команды (нужно `0x10`…`0x14`) или не тот номер таблицы |
| Ответа нет | адрес, линия, направление DE/RE; на вещание (адрес 0) ответа не будет никогда |
| `EEPROM` биты 1…3 = 0 после `0x12`/`0x13`/`0x14` | результат не принят автоматом (например, сумма углов > 360°) — повторить этап; в EEPROM ничего плохого не записалось |
| Всё сломано | `CAL_CMD := 0x10`, перезагрузка — таблицы вернутся из EEPROM; если перезаписаны хуже прежних, восстановить из `ang_tab_before.csv` нельзя, нужна прошивка/повторная калибровка |

## 6. Готовые кадры

Головка с адресом 1, 115200 8E1. Для другого адреса пересчитать CRC16
(`python3 tools/modbus_calib.py frames -s <адрес>`). Один кадр — одна команда.

| Действие | Кадры (запрос → ожидаемый ответ) |
|---|---|
| `0x14` buf_k | `01 06 00 01 00 14 D8 05` → то же эхо |
| `0x13` offset | `01 06 00 01 00 13 99 C7` → то же эхо |
| `0x11` проход 1 | `01 06 00 01 00 11 18 06` → то же эхо |
| `0x12` проход 2 | `01 06 00 01 00 12 58 07` → то же эхо |
| `0x10` стоп | `01 06 00 01 00 10 D9 C6` → то же эхо |
| Опрос статуса | `01 04 00 0B 00 14 81 C7` → `01 04 28 …` (40 байт данных) |
| Только `STATE` | `01 04 00 0B 00 01 40 08` |
| Страница 0 `ang_tab` | `01 06 00 02 00 00 28 0A` → `01 04 00 1F 00 20 C0 14` |
| Страница 1 `ang_tab` | `01 06 00 02 00 10 29 C6` → тот же запрос FC04 |

После `0x14` и `0x13` не отправлять следующую команду, пока в `STATE` не
появился код готовности (`0x80`, `0x60`), а в `EEPROM` — бит 0.
