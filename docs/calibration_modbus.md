# Самокалибровка головки вручную: команды по RS-485 / Modbus RTU

Документ описывает, **как запустить, вести и завершить самокалибровку конкретной
считывающей головки, отправляя команды прямо в шину** — с ПК через адаптер
USB↔RS485 и любой Modbus-инструмент, либо через `tools/modbus_calib.py`.

Алгоритмы и их математика — в
[`angle_math_and_calibration.md`](angle_math_and_calibration.md) (разделы §8–§13);
общая линия связи, пины и карта снимка — в [`modbus_rtu.md`](modbus_rtu.md). Здесь —
только протокол управления, последовательность и контроль хода.

---

## 1. Что реализовано

Исторически калибровки запускались командами `0x10…0x14` по SPI; вместе с SPI-каналом
исчез и обработчик команд, а конечные автоматы остались. Реализованный канал
восстанавливает те же коды поверх Modbus RTU, **не трогая `Src/main.c`**:

| Файл | Назначение |
|---|---|
| `Inc/encoder_vars.h` | extern-мост к переменным калибровки, определённым в `Src/main.c` (согласованность типов проверяет `tests/encoder_vars_test.py`) |
| `Inc/modbus_calib.h` | карта holding/input-регистров, коды команд, биты флагов и предупреждений |
| `Src/modbus_calib.c` | приём команды с защитой, запуск/останов/откат автоматов, живой статус, окно выгрузки таблиц |
| `Src/modbus_registers.c` | маршрутизация FC06/FC04 и перевод отказов в исключения Modbus |
| `tools/modbus_calib.py` | ручная отправка (`frames`, `cmd`), наблюдение (`watch`), автомат (`run`), выгрузка таблиц (`dump`) |

Три свойства реализации важны именно для ручной работы:

* **запрос адресный — и это важно не только ради ответа.** FreeModbus исполняет и
  **вещательный** кадр (адрес 0): запись доходит до обработчика регистров на *каждой*
  головке, просто ответ не формируется (`mb.c`, `eMBPoll()`). Поэтому калибровку по
  адресу 0 послать «технически» можно — и она запустится на всех головках сразу, без
  подтверждения и без возможности увидеть отказ. Вещание для `CAL_*` **запрещено
  процедурой**, а `tools/modbus_calib.py` отказывается работать с `-s 0` (для `SNAP`
  адрес 0 легален и остался отдельным путём в `Src/modbus_registers.c`);
* **ничего не выполняется в прерывании.** FreeModbus вызывает обработчик регистров
  из `eMBPoll()` в основном цикле `main()`, то есть в том же контексте, где живут
  конечные автоматы. Команда только взводит флаги, а автомат крутится дальше сам —
  жёсткое реальное время кадра не срывается;
* **статус читается в любой момент**, в том числе прямо во время вращения:
  обработчик FC04 и автоматы работают в одном контексте, поэтому гонки нет.

## 2. Регистровая карта

### 2.1 Запись (FC06, holding) — адреса «на проводе», с нуля

| Адрес | 4x-формат | Имя | Содержание |
|---|---|---|---|
| 0 | 400001 | `SNAP` | зафиксировать снимок кадра (номер последовательности) — существующий регистр |
| 1 | 400002 | `CAL_CMD` | код команды `0x10…0x14` |
| 2 | 400003 | `CAL_KEY` | `0xCA1B` — разрешить **ровно одну** команду; любое другое значение — запереть |
| 3 | 400004 | `CAL_CFG` | bit0 `RELAX` — не проверять условия запуска; bit1 `KEEP` — при `0x10` не откатывать `offset`/`buf_k` |
| 4 | 400005 | `CAL_PAGE` | окно выгрузки таблиц: `[15:8]` — номер таблицы, `[7:0]` — индекс первого элемента |

### 2.2 Коды команд и ожидаемые коды состояния

| Команда | Что делает | `encoder_state` сразу | …и по завершении |
|---|---|---|---|
| `0x10` | аварийный стоп: снимает все флаги, включает АРУ подсветки, откатывает прерванные `offset`/`buf_k` | `0x00` | — |
| `0x11` | `angtab_cal()`, **проход 1** (вращение «вправо») | `0x10` | `0x20` |
| `0x12` | `angtab_cal()`, **проход 2** (вращение «влево»), затем усреднение, применение и запись в EEPROM | `0x30` | `0x40` |
| `0x13` | `offset_cal()` — перебор точки съёма | `0x50` | `0x60` |
| `0x14` | `angk_cal()` — выравнивание чувствительности пикселей | `0x70` | `0x80` |

### 2.3 Чтение (FC04, input) — живой блок калибровки

Блок идёт сразу за снимком кадра (регистры `0…10`) и, в отличие от снимка, **не
зависит от SNAP**: значения актуальны на момент запроса. Полный опрос —
`FC04, адрес 11, количество 36`.

| Адрес | Имя | Смысл |
|---|---|---|
| 11 | `BLOCK_ID` | `0xCA10` — прошивка с блоком калибровок (иначе читать нечего) |
| 12 | `STATE` | `encoder_state` |
| 13 | `AUTO_CAL` | 0 — нет, 1 — проход 1, 2 — проход 2 |
| 14, 15 | `RDY1`, `RDY2` | **прогресс проходов `ang_tab`, 0…144** |
| 16 | `OFFSET_PHASE` | фаза `offset_cal` (0/1/2/3/4/5/100/101) |
| 17, 18 | `OFFSET_CUR`, `OFFSET_FOUND` | текущая проба и найденный оптимум |
| 19 | `OFFSET_X256` | живой `offset`, 1/256 пикселя |
| 20, 21 | `ANGLEK_PHASE`, `ANGLEK_CUR` | фаза автомата `angk_cal` (0…8, 100, 101) и номер кандидата усиления `buf_k` |
| 22 | `PIXMINMAX` | `pix_min_max`, отсчёты АЦП (цель < 100) |
| 23–24 | `MINMAX` | `min_max` — размах остатка, **знаковые микроградусы** (int32); `status`/`watch` делят их на 3,6 и печатают в угловых секундах |
| 25 | `REVS` | `avg_minmax_num` — сколько оборотов учтено в текущей пробе |
| 26, 27 | `REV_RIGHT`, `REV_LEFT` | счётчики оборотов по направлениям |
| 28, 29 | `SERR1`, `SERR2` | `serrcnt1` (брак кадров), `serrcnt2` (сработавшие коррекции) |
| 30 | `SECTOR` | текущий сектор |
| 31–32 | `ANGLE` | живой `cur_ang_E`, микроградусы — по нему видно направление вращения |
| 33 | `FLAGS` | битовые флаги, §2.4 |
| 34 | `DIAG` | предупреждения, §2.5 |
| 35 | `LAST_CMD` | код последней команды |
| 36 | `LAST_RESULT` | 0 — принято, 1…6 — причина отказа, §2.6 |
| 37, 38 | `CMD_COUNT`, `REJ_COUNT` | принято / отклонено команд (16 бит, переполняются) |
| 39–40 | `CYCLES` | `cycles_max`, такты |
| 41 | `BACKLIGHT` | `backlight_width_ticks` — регулировка яркости (АРУ) |
| 42 | `TEMP` | температура кристалла, 0,1 °C |
| 43, 44 | `PIX_AVG`, `OFFSET_AVG` | `pix_dif_num_avg`, `offset_avg_num` (настройки глубины усреднения) |
| 45–46 | `SAMPLE` | счётчик обработанных кадров АЦП: не растёт — кадров нет вообще |
| 47…78 | `WINDOW` | окно выгрузки: 16 float = 32 регистра, IEEE-754, старшее слово первым |

Идентификаторы таблиц для `CAL_PAGE`: `0` — `ang_tab[144]`, `1` — `buf_k[128]`,
`2` — `pix_dif_tab1[144]`, `3` — `pix_dif_tab2[144]`, `4` — `offset_minmax[128]`.
Страница — 16 элементов, индекс заголовка прижимается к концу таблицы, так что
выйти за границы нельзя. Полная `ang_tab` — 9 страниц.

### 2.4 `FLAGS` (адрес 33)

| Бит | Имя | Что означает единица |
|---|---|---|
| 0 | `CAL_PENDING` | `start_calibrate` ещё не съеден автоматом |
| 1 | `OFFSET_RUN` | идёт `offset_cal` |
| 2 | `ANGK_RUN` | идёт `angk_cal` |
| 3 | `REV_EN` | детектор перехода через 0/360 взведён |
| 4 | `AGC_ON` | АРУ подсветки разрешена (на время `0x14` должна быть **снята**) |
| 5 | `EEPROM_IDLE` | `i2c3_tx_wp = 1`, запись в EEPROM завершена |
| 6 | `ERROR` | `errorflag`: последний кадр бракован |
| 7 | `ARMED` | ключ `CAL_KEY` взведён, ждёт ровно одну команду |
| 8 | `RELAX` | проверки условий запуска отключены |
| 9 | `KEEP` | откат при `0x10` выключен |
| 10…13 | `ANG_TAB_RDY`, `BUF_K_RDY`, `OFFSET_RDY`, `LASDAC_RDY` | блок принят из EEPROM при старте (CRC16 сошлась) |
| 14 | `BUSY` | идёт калибровка — новые пусковые команды будут отклонены |
| 15 | `WAIT_PASS2` | состояние `0x20`: проход 1 готов, ждём `0x12` |

### 2.5 `DIAG` (адрес 34) — «что-то идёт не так» сразу на экране

Приращения считаются **относительно предыдущего чтения** блока, поэтому диагностика
осмысленна при периодическом опросе (режим `watch` делает это сам). Первое чтение
только задаёт базу — бить тревогу оно не может.

| Бит | Имя | Как трактовать |
|---|---|---|
| 0 | `MOVING_RIGHT` | угол растёт — это нужно для команды `0x11` |
| 1 | `MOVING_LEFT` | угол убывает — это нужно для `0x12` |
| 2 | `WRONG_DIRECTION` | направление не соответствует текущему проходу → развернуть |
| 3 | `ANGTAB_STALLED` | прогресс `ang_tab` между опросами не двигался |
| 4, 5 | `OFFSET_STALLED`, `ANGK_STALLED` | фаза автомата не меняется |
| 6 | `MINMAX_UP` | `min_max` вырос относительно прошлого опроса |
| 7 | `SERR_GROWING` | прибавляются `serrcnt1` — кадры бракуются, калибровка по ним не идёт |
| 8 | `NO_REVS` | оборот не детектируется: скорость слишком велика или данных нет |
| 9 | `EVERY_OTHER` | прогресс застрял на **72** — обход каждый второй сектор |
| 10 | `NO_FRAMES` | между опросами не обработано ни одного кадра АЦП |

### 2.6 Отказы: что видно на шине

| Причина (возврат модуля) | Исключение Modbus | Смысл |
|---|---|---|
| `MB_CAL_ERR_REG` (1) | `0x02` | нет такого holding-регистра / адрес вне карты FC04 |
| `MB_CAL_ERR_VALUE` (2) | `0x04` | неизвестный код команды, неизвестный номер таблицы |
| `MB_CAL_ERR_LOCKED` (3) | `0x04` | не взведён `CAL_KEY` |
| `MB_CAL_ERR_BUSY` (4) | `0x06` SLAVE_BUSY | уже идёт другая калибровка |
| `MB_CAL_ERR_EEPROM` (5) | `0x06` SLAVE_BUSY | предыдущий блок ещё пишется в EEPROM |
| `MB_CAL_ERR_PREREQ` (6) | `0x04` | нарушен порядок: `0x12` без завершённого прохода 1, `0x11/0x12` при неизвестном или физически невозможном `offset` |

Точная причина дублируется в `LAST_RESULT` — удобно, когда инструмент показывает
только номер исключения. При вещании (адрес 0) исключения не будет: команда
исполнится, но ответ не отправляется, поэтому отказ выглядит как «головка
промолчала», а принята она может быть одновременно всеми головками шины.

## 3. Защита записи EEPROM

Завершённая калибровка **сама** пишет результат в EEPROM (от 6 до 578 байт + CRC16),
на время записи снимая аппаратную защиту WP с вывода `PA9`. Поэтому в канал
встроены четыре предохранителя:

1. **Ключ-затвор.** Команда `0x11…0x14` исполняется, только если непосредственно
   перед ней в `CAL_KEY` было записано `0xCA1B`. Ключ гаснет сразу после принятия
   команды (one-shot): случайный повтор кадра в шине или «залипший» опросник не
   смогут запустить калибровку второй раз. При отказе (занято, нет ключа-условия)
   ключ **не** сгорает — можно исправить условия и повторить команду.
2. **Занятость.** Пока автомат идёт (`BUSY`), все пусковые команды отклоняются.
3. **EEPROM.** Пока `i2c3_tx_wp = 0` (запись не завершена), пусковые команды
   отклоняются: нельзя начать новую калибровку поверх незаписанного результата.
4. **Откат.** Прерванная калибровка `offset`/`buf_k` возвращает в RAM состояние на
   момент запуска (в EEPROM к этому моменту не записано ничего) и восстанавливает
   разрешение АРУ подсветки. Отключается флагом `KEEP`.

`0x10` (стоп) — **единственная команда без ключа и без проверок**: аварийный выход
не должен оказаться запертым собственной защитой. В отличие от исторического
SPI-`0x10` она гасит и `start_angk_cal`, и возвращает `backlight_width_en`, так что
прерванная калибровка `buf_k` больше не «продолжится сама» (проблема, отмеченная в
§12.4 математики).

## 4. Подготовка

| Пункт | Зачем |
|---|---|
| Головка собрана, диск закреплён без люфта, оптика чистая | эксцентриситет и наклон диска методом замыкания **не** убираются |
| Привод — **мотор**, вращение равномерное | `find_avg()` считает остаток при линейном `θ(t)`; рывок рукой даёт ложный размах |
| Скорость для `0x13`/`0x14`: 10…40 об/мин (жёстко < 57) | выше — переход через 0/360 не детектируется, автоматы встают |
| Скорость для `0x11`/`0x12`: 5…20 об/мин (жёстко < 81) | строб шириной 1 пиксель «перепрыгивается» |
| Шина: 115200 **8E1**, адрес головки известен, терминал в hex | другую конфигурацию `xMBPortSerialInit()` не принимает |
| `BLOCK_ID == 0xCA10`, `SAMPLE` растёт, `SERR1` не растёт | прошивка с блоком калибровок, кадры идут, декодер жив |
| **Выгрузить `ang_tab` и `buf_k` в CSV** | страховка: `dump` — единственный способ вернуться к исходным таблицам |

```bash
python3 tools/modbus_calib.py status -s 3 --port /dev/ttyUSB0
python3 tools/modbus_calib.py dump   -s 3 --port /dev/ttyUSB0 --table ang_tab --csv ang_tab_before.csv
python3 tools/modbus_calib.py dump   -s 3 --port /dev/ttyUSB0 --table buf_k   --csv buf_k_before.csv
```

Отдельно — **проверить направление вращения** до калибровки `ang_tab`: в `watch`
должен расти либо `REV_RIGHT`, либо `REV_LEFT`.

## 5. Последовательность команд

Порядок не произволен: `buf_k` улучшает субпиксельную оценку, от неё зависит качество
`offset`, а `offset` задаёт геометрический строб для `ang_tab` (см. §12.1 математики).

```
  ┌───────────────┐   ┌───────────────┐   ┌────────────────┐   ┌────────────────┐
  │ 0x14  buf_k   │──▶│ 0x13  offset  │──▶│ 0x11  ang_tab  │──▶│ 0x12  ang_tab  │
  │ 10…40 об/мин  │   │ 10…40 об/мин  │   │   1-й проход   │   │   2-й проход    │
  │любое направл. │   │любое направл. │   │   угол РАСТЁТ   │   │  угол УБЫВАЕТ  │
  └───────┬───────┘   └───────┬───────┘   └───────┬────────┘   └───────┬────────┘
          ▼                   ▼                   ▼                     ▼
      state=0x70          state=0x50           state=0x10              state=0x30
      … вращаем …         … вращаем …          … вращаем …             … вращаем …
          ▼                   ▼                     ▼                      ▼
      state=0x80          state=0x60           state=0x20              state=0x40
      EEPROM записан      EEPROM записан     «ждём команду 0x12»        EEPROM записан
      (EEPROM_IDLE=1)     (EEPROM_IDLE=1)                                │
                                                                          ▼
                                                                    0x10, стоп
```

**Общий ритм одного шага:**

1. `CAL_KEY := 0xCA1B` (ключ нужен на каждую пусковую команду);
2. `CAL_CMD := код`;
3. убедиться, что `STATE` перешёл в «идёт» (0x10/0x30/0x50/0x70), а
   `LAST_RESULT = 0`;
4. **включить равномерное вращение** и не останавливать его до конца шага;
5. читать статус (`FC04, адрес 11, 36`) с интервалом 0,2…1 с, следя за `DIAG`;
6. дождаться кода «готово» (0x20/0x40/0x60/0x80);
7. дождаться `EEPROM_IDLE = 1` — только тогда результат реально в памяти;
8. следующий шаг.

### 5.1 Кадры для ручной отправки

Готовые RTU-кадры (CRC16 уже посчитана) для головки с адресом `1`. Для другого
адреса меняется первый байт и CRC; проще всего получить их командой
`python3 tools/modbus_calib.py frames -s <адрес>` — или собрать в любом
Modbus-инструменте: функция 6, адрес 1 (команда) или 2 (ключ), значение.

| Шаг | Действие | Кадр |
|---|---|---|
| — | ключ на одну команду | `01 06 00 02 CA 1B 3E A1` |
| 1 | `0x14` buf_k | `01 06 00 01 00 14 D8 05` |
| 2 | `0x13` offset | `01 06 00 01 00 13 99 C7` |
| 3 | `0x11` ang_tab, проход 1 | `01 06 00 01 00 11 18 06` |
| 4 | `0x12` ang_tab, проход 2 | `01 06 00 01 00 12 58 07` |
| — | `0x10` стоп (без ключа) | `01 06 00 01 00 10 D9 C6` |
| — | статус, 36 регистров | `01 04 00 0B 00 24 81 D3` |
| — | только код состояния | `01 04 00 0C 00 01 F1 C9` |

Ответ на FC06 при успехе — эхо запроса (8 байт); при отказе — 5 байт
`адрес 86 код_исключения crc`. Ответ на FC04 (36 регистров) — 77 байт.

### 5.2 Шаг 1 — `buf_k` (`0x14`)

| | |
|---|---|
| Отправить | ключ, затем `0x14` |
| Ожидать сразу | `STATE = 0x70`, `AGC_ON = 0`, `ANGLEK_PHASE = 0` |
| Режим вращения | 10…40 об/мин, **любое** направление |
| Контроль | `ANGLEK_PHASE`: 0→1→2→3→4→…→8→100→101; на фазах 1…8 растёт `REVS`; `PIXMINMAX` убывает к <100 |
| Готово | `STATE = 0x80`, затем `EEPROM_IDLE = 1` |
| Время | 50…70 оборотов: ≈2,5…3,5 мин при 20 об/мин |
| Особенность | зависание на фазе 2 (`ANGK_STALLED`, `PIXMINMAX ≥ 100`) — грязь или блик: прервать `0x10`, обслужить оптику, повторить |

### 5.3 Шаг 2 — `offset` (`0x13`)

| | |
|---|---|
| Отправить | ключ, затем `0x13` |
| Ожидать сразу | `STATE = 0x50`, `OFFSET_PHASE = 0`, `OFFSET_CUR = 63` |
| Режим вращения | 10…40 об/мин, любое направление |
| Контроль | `OFFSET_CUR` перебирает 63→65, при необходимости 56…72; `MINMAX` должна **падать**; `REVS` прирастает на 4 за пробу |
| Готово | `OFFSET_PHASE = 100`, `STATE = 0x60`, `OFFSET_FOUND` — итог; `EEPROM_IDLE = 1` |
| Время | 12…40 оборотов: ≈36 с…2 мин |
| Особенность | `OFFSET_X256/256` во время перебора «гуляет» по окну — это пробы, а не результат; `0x10` вернёт `offset` обратно |

### 5.4 Шаг 3 — `ang_tab`, проход 1 (`0x11`)

| | |
|---|---|
| Проверить до старта | растёт `REV_RIGHT` (угол увеличивается); иначе сначала сменить направление вращения |
| Отправить | ключ, затем `0x11` |
| Ожидать сразу | `STATE = 0x10`, `AUTO_CAL = 1` |
| Режим вращения | 5…20 об/мин, **угол должен расти** |
| Контроль | `RDY1` монотонно 0→144 |
| Готово | `STATE = 0x20`, `WAIT_PASS2 = 1` — в EEPROM ещё ничего не писалось |
| Время | 1…3 оборота |
| Особенность | `RDY1` застрял на **72** (`DIAG.EVERY_OTHER`) → `0x10`, сменить направление, повторить `0x11` |

### 5.5 Шаг 4 — `ang_tab`, проход 2 (`0x12`)

| | |
|---|---|
| Условие пуска | `STATE == 0x20`, иначе отказ `PREREQ` (усреднение с незаполненной таблицей прохода 1 испортило бы `ang_tab`) |
| Отправить | ключ, затем `0x12` |
| Ожидать сразу | `STATE = 0x30`, `AUTO_CAL = 2` |
| Режим вращения | 5…20 об/мин, **угол должен убывать** (`REV_LEFT`) |
| Контроль | `RDY2` монотонно 0→144 |
| Готово | `STATE = 0x40` — таблица применена и отправлена в EEPROM |
| Время | 1…3 оборота |
| Важно | `0x12` без `0x11` (по `RELAX`) — только осознанный эксперимент: результат усреднится с нулями |

### 5.6 Шаг 5 — верификация

1. `0x10` (стоп) → `STATE = 0x00`, `AGC_ON = 1`;
2. дождаться `EEPROM_IDLE = 1` (∼1 с после 0x40/0x60/0x80);
3. **перезагрузить головку** и прочитать `FLAGS`: `ANG_TAB_RDY`, `BUF_K_RDY`,
   `OFFSET_RDY` должны остаться установленными — это подтверждение, что CRC16
   блоков в EEPROM сошлась и калибровка пережила выключение питания;
4. выгрузить таблицы повторно и сравнить с «до»:
   `python3 tools/modbus_calib.py diff ang_tab_before.csv ang_tab_after.csv` —
   `ang_tab` отличается от исходной на десятые доли градуса, `buf_k` имеет разброс
   около единицы;
5. снять диагностический прогон вращения и сравнить `MINMAX` до и после — размах
   остатка должен заметно упасть.

## 6. Ведение процесса в терминале

```bash
# два окна: в одном команды, в другом — живой статус
python3 tools/modbus_calib.py watch  -s 3 --port /dev/ttyUSB0 --interval 0.5
python3 tools/modbus_calib.py cmd    -s 3 --port /dev/ttyUSB0 --cmd 0x14
python3 tools/modbus_calib.py cmd    -s 3 --port /dev/ttyUSB0 --cmd 0x10   # стоп
```

Полный автомат (подсказывает, когда сменить направление, ждёт состояния и
`EEPROM_IDLE`):

```bash
python3 tools/modbus_calib.py run -s 3 --port /dev/ttyUSB0
python3 tools/modbus_calib.py run -s 3 --port /dev/ttyUSB0 --only 0x11   # один шаг
```

Без `pyserial` и без «умной» утилиты работают два режима: `frames` (готовые кадры)
и `map` (таблица регистров и битов). Опрос раз в 0,2…1 с реальному времени не
мешает; гонять шину на 100 Гц не стоит — каждый запрос обрабатывается в основном
цикле между кадрами АЦП.

## 7. Диагностика: симптом → регистры → действие

| Симптом | Где видно | Что делать |
|---|---|---|
| Команда отклонена, исключение `0x04` | `LAST_RESULT = 3` | взвести `CAL_KEY` и повторить команду |
| Исключение `0x06` SLAVE_BUSY | `LAST_RESULT = 4`, `FLAGS.BUSY` | дождаться конца текущего шага (или подать `0x10`) |
| Исключение `0x06`, но `BUSY = 0` | `LAST_RESULT = 5`, `FLAGS.EEPROM_IDLE = 0` | подождать ∼1 с: идёт запись в EEPROM |
| Исключение `0x04`, `LAST_RESULT = 6` | порядковое условие | `0x11/0x12`: сначала `offset`; `0x12`: сначала завершить `0x11`. Осознанный обход — `CAL_CFG = 1` (RELAX) |
| `RDY1`/`RDY2` стоит на 72 | `DIAG.EVERY_OTHER` | `0x10`, сменить направление, повторить проход |
| `RDY1`/`RDY2` не растёт совсем | `DIAG.ANGTAB_STALLED` | снизить скорость (строб 1 пиксель!), проверить `ERROR`/`SERR1` |
| `REVS` не растёт, фазы стоят | `DIAG.NO_REVS` | скорость слишком велика — замедлить |
| Растёт `SERR1` | `SERR1`, `FLAGS.ERROR` | калибровка по бракованным кадрам не идёт: фокус, чистота, скорость |
| `ANGLEK_PHASE` завис на 2 | `DIAG.ANGK_STALLED`, `PIXMINMAX ≥ 100` | грязь/блик; `0x10` (откатит `buf_k`), обслужить оптику, повторить |
| `MINMAX` не падает | `MINMAX` | неравномерный привод или биение диска |
| `SAMPLE` не растёт | `DIAG.NO_FRAMES` | головка не видит кадров: питание, тактирование линейки, DMA |
| `CYCLES` близок к бюджету кадра | `CYCLES` | длинный блок (EEPROM/DMA) давит реальное время — увеличить паузы между запросами |
| После перезагрузки `*_RDY = 0` | `FLAGS` | CRC16 блока не сошлась: проверить микросхему EEPROM (запись 578 байт одной транзакцией, §9.6 математики) |

## 8. Границы подтверждённого

Хостовые проверки покрывают логику канала, но **не** моделируют тактирование USART,
DE/RE, реальную линию RS-485 и EEPROM:

```bash
python3 tests/calib_map_test.py       # карта регистров: прошивка ↔ утилита
python3 tests/encoder_vars_test.py    # типы extern-моста совпадают с Src/main.c
sh tests/host/run_calib_test.sh       # кадры RTU → флаги, исключения, откат, окно выгрузки
sh tests/host/run_rtu_test.sh
sh tests/host/run_snapshot_test.sh
```

Порядок проверки на оборудовании: сначала `status` (должен вернуться `BLOCK_ID`,
а `SAMPLE` — расти при вращении), затем ключ + `0x14` на короткое время и `0x10` —
убедиться, что `AGC_ON` вернулся и `buf_k` откатилась, а `CAL_KEY` погас; после этого —
полный цикл на **одной** головке и только потом — проверка, что вторая головка на
запрос первой не отвечает и не меняет своего `STATE` (это и есть проверка
адресности). Отдельно убедиться осциллографом, что на вещание ответы не идут.

**Чего в канале сознательно нет:** записи произвольных значений в `ang_tab`/`buf_k`
(восстановить «заводскую» таблицу можно только прошивкой/отладчиком — выгрузка сделана
для сравнения и архива), смены адреса Modbus по шине и калибровки по вещанию.
