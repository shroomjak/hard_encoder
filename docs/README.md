# Документация проекта `hard_encoder`

Сводный указатель технической документации, сквозная схема тракта измерения угла и реестр выявленных и устранённых дефектов прошивок STM32F722RE, ESP32 и диагностического ПО.

## 1. Структура документации

| Документ | Содержание |
|---|---|
| [`main_c_overview.md`](main_c_overview.md) | Аппаратные узлы STM32F722RE, приоритеты `NVIC`, тайминг кадра `TSL1401CL` (`~103 мкс`), `O(1)`-конвейер обработки, карта EEPROM и диспетчер калибровки |
| [`angle_math_and_calibration.md`](angle_math_and_calibration.md) | Геометрия 144-секторного диска, двухреперный фильтр префиксных сумм, табличное декодирование и `Chase-1`, ядро `BR4_C`, временна́я синхронизация `age_us -> t_snap`, полуразность противоположных головок и 4 этапа самокалибровки |
| [`modbus_rtu.md`](modbus_rtu.md) | Протокол RS-485 / Modbus RTU (`230400 8E1`), карта регистров `SNAP` и `LIVE`, конечные автоматы `poll` и `calib`, ограничения страничной записи EEPROM и набор хост-тестов |
| [`../esp32_master/README.md`](../esp32_master/README.md) | Команды консоли мастера ESP32 (`scan`, `use`, `poll`, `calib`, `next`, `stop`, `status`), распиновка и формат строк `DATA` |

## 2. Сквозной тракт измерения и синхронизации

| Уровень | Тактирование / период | Выполняемая операция |
|---|---|---|
| Оптический кадр головки (`Src/main.c`) | `T_frame ≈ 103 мкс` (`~9.7 кГц`), `DWT = 216 МГц` | Считывание `128` фотодиодов `TSL1401CL` (`ADC2 + DMA2_Stream3`), фиксация метки середины вспышки `exp_cyccnt` (`18.52 мкс`), расчёт угла за константное время `O(1)` и публикация в `latest_slots[2]` |
| Широковещательная фиксация `SNAP` (`Src/modbus_port.c`, `Src/snapshot_registers.c`) | Период `10.000 мс` (`100.000 Гц`, `esp_timer` ISR) | Пакет `00 06 00 00 seq crc` по шине `230400 8E1`; захват `snap_rx_cyccnt` по стоп-биту, защёлкивание `frozen` в `TIM2_IRQHandler` (`t3.5 = 200 мкс`) и вычисление `age_us = round((snap_rx_cyccnt - exp_cyccnt) / 216)` |
| Адресный сбор и приведение к `t_snap` (`esp32_master/main/`) | Core 0 (`encoder_bus`), `~2.1 мс` на головку | Поочерёдное чтение `FC04` (`11` регистров `0..10`), проверка `seq / ready / error / age_us` и линейная скоростная экстраполяция каждого канала с момента экспозиции `t_us - age_us` к общему моменту `t_us` |
| Потоковая передача и диагностика (`pc_link.c`, `diagnostics/`) | Core 1, `UART0` `921600 8N1` (`APB = 80 МГц`) | Передача через неблокирующий `RINGBUF_TYPE_NOSPLIT` (`64 КБ`), запись CSV (`serial_head_logger.py`), спектральный и регрессионный анализ по `360°`-оборотам (`head_period_analysis.py`, `residual_plots.py`) |

## 3. Реестр выявленных и устранённых дефектов

### 3.1. Конвейер считывания и вычисления угла на STM32 (`Src/main.c`, `Src/snapshot_registers.c`)

| Узел | Проблема исходной реализации | Внесённое исправление |
|---|---|---|
| `DMA2_Stream3_IRQHandler` | Разрешение прерываний до останова `TIM3` либо снижение приоритета `NVIC` ниже `0` приводило к проскакиванию лишнего такта `T-CLK` (`0.61 мкс`) при совпадении с байтом `USART1` и сдвигу пикселей в буфере DMA | Высший приоритет `NVIC = 0` и маскирование `PRIMASK = 1` сохранены на всём критическом участке перезапуска линейки; внутри паузы `DelayTim4Ticks` добавлен неразрушающий опрос `modbus_poll_rx_cyccnt()` (точность метки `SNAP` `< 0.7 мкс`) |
| `DWT->CYCCNT` в суперцикле | Обнуление `DWT->CYCCNT = 0` на каждом кадре разрушало общую шкалу времени между экспозицией и приёмом `SNAP` | Счётчик переведён в непрерывный циклический режим `216 МГц`; длительность кадра считается разностью `(uint32_t)(DWT->CYCCNT - frame_start_cyccnt)` |
| `find_startpixel()` | Вложенные циклы суммирования создавали лишнюю нагрузку на каждом из `51` сдвигов | Введён массив префиксных сумм `pref[129]` (`O(1)` на сдвиг по диапазону пикселей `6..126`) |
| `mes_piks()` + `BR4_C()` | Массив `buf_x2` заполнялся только на `[star_pixel + 4, star_pixel + 16)`, тогда как ядро `BR4_C` обращается к `[max_X0 - 3 .. max_X0 + 3]` (`star_pixel + 1 .. star_pixel + 18`), читая устаревшие отсчёты от предыдущих кадров; при нулевом сигнале `max_X0` оставался равным `0` (выход за нижнюю границу массива `buf_x2[-3]`) | Окно масштабирования `buf_x2[i] = buf_x1[i] * buf_k[i]` расширено на `[star_pixel + 1, star_pixel + 19)` (`7..125`); `max_X0` инициализируется значением `star_pixel + 10` |
| `calc_sector()` и `bit_err_corr()` | Линейный перебор `bit_tab[144]` и итеративный перебор бит давали переменное время кадра и джиттер публикации | Введена константная таблица во Flash `sector_by_code[512]` (`O(1)`) и одношаговая мягкая коррекция `Chase-1` инверсией бита `0x100U >> badbit_pos` при `badbit_value < 1000` |
| `err_corr()` | Проверка непрерывности опиралась на `sec_cnt < 50`, который обнулялся только по `errorflag` и переставал защищать от скачков сектора после первых 50 ошибок | Введён явный флаг достоверности истории `sector_history_valid`, сбрасываемый при любом некорректном кадре и восстанавливаемый после первого валидного сектора |
| `angle_deg_to_udeg()` | Преобразование `(double)angle * 1000000.0` вызывало программную эмуляцию `double` на однопрецизионном FPU Cortex-M7 (`FPv5-SP-D16`) | Заменено точным целочисленным масштабированием 24-битной мантиссы IEEE-754 `float` через `uint64_t` |
| АРУ подсветки | Переменная ширина импульса `backlight_width_ticks` смещала эффективный центр экспозиции на динамических режимах | В `main()` зафиксированы `agc_test_disable = 1U` и `backlight_width_ticks = 2000` (`18.52 мкс`) |

### 3.2. Режим самокалибровки и EEPROM (`Src/main.c`, `Src/encoder_calibration.c`, `esp32_master/main/`)

| Узел | Проблема исходной реализации | Внесённое исправление |
|---|---|---|
| Разделение ответственности и порядок вызовов | В суперцикле `Src/main.c` напрямую вызывались подряд `offset_cal(); angk_cal(); angtab_cal();` в порядке, обратном физическим зависимостям параметров, без защиты от одновременной активации нескольких автоматов | Оркестрация последовательности (`0x14 -> 0x13 -> 0x11 -> 0x12 -> 0x10`) закреплена исключительно за `esp32_master/main/workflow.c`; в `Src/encoder_calibration.c` введён единый диспетчер `encoder_calibration_step()`, исполняющий не более одного этапа и сбрасывающий все автоматы в `STOP` при коллизии флагов |
| Рабочий диапазон `angk_cal()` | Выравнивание `buf_k` выполнялось только для индексов `15..120` (а поиск провалов — `16..120`), тогда как `find_startpixel` и `mes_piks + BR4_C` используют пиксели `6..126` (`STARTPIXEL_MIN = 6`, правая граница шаблона `56 + 70 = 126`, ядро `BR4_C` `7..125`). На `~20%` длины каждого сектора крылья `BR4_C` пересекали ступеньку между калиброванными (`buf_k != 1`) и некалиброванными (`buf_k == 1`) пикселями | Диапазон выравнивания `angk_cal()` расширен до `[ANGK_CAL_PIX_MIN..ANGK_CAL_PIX_MAX] = [6..126]`, поиск слабых вершин репера — до `[10..122]`, неиспользуемые краевые индексы `[0..5]` и `127` принудительно удерживаются равными `1.0f` |
| Огибающая `buf_x3` и деление на ноль в `angk_cal()` | Массив максимумов `buf_x3[]` не очищался после пересчёта `buf_k` в фазах 1 и 2 (фаза 2 анализировала устаревшие пики до коррекции); при затенённых пикселях `buf_x3[64] / buf_x3[i]` порождало `+Inf`/`NaN` в EEPROM и потенциально бесконечный цикл в фазе 2; литерал `1.04` без суффикса `f` вызывал `double`-арифметику | Добавлены очистка `memset(buf_x3, 0, sizeof(buf_x3))` при старте и после каждого пересчёта в фазах 1 и 2, порог валидного пика `ANGK_MIN_VALID_PEAK = 50.0f` с ограничением `buf_k ∈ [0.25, 4.0]`, лимит `ANGK_PHASE2_MAX_ITERS = 5` и константы `1.04f` |
| Расширение окна `offset_cal()` | Граничная проверка использовала жёсткую константу `64` (`offset_min_num < 64` / `> 64`) вместо фактических границ окна `[offset_start, offset_end]` | Условие расширения привязано к реальным краям `offset_start` и `offset_end` с ограничением расширенных границ `left_limit` / `right_limit` диапазоном `[0..127]` |
| Опрос `LIVE` в `WF_CALIB` на ESP32 | В `esp32_master/main/main.c` режим `WF_CALIB` разделял нулевой таймаут очереди с `WF_SCAN`, из-за чего задача `encoder_bus` (приоритет `9`, Core 0) непрерывно читала `FC04` без паузы (~800 кадров/с), вызывая голодание `IDLE0` (срабатывание Task Watchdog через `5 с`) и лишнюю нагрузку прерываний `USART1` на головке | Режим `WF_CALIB` выделен на интервал ожидания очереди `CALIB_LIVE_POLL_MS = 50 мс` (`20 Гц` опроса `LIVE` с мгновенным откликом на команду `stop`) |
| Ошибка шины `I2C3` | При сбое записи EEPROM вывод защиты `WP` (`PA9`) оставался в активном низком состоянии (`0`) | В `HAL_I2C_ErrorCallback()` добавлены фиксация `i2c3_err = 1` и немедленный возврат защиты записи `PA9 = 1` при сохранении `i2c3_tx_wp = 0` |

### 3.3. Шина RS-485, таймер `poll` и канал ПК на ESP32 (`esp32_master/`, `Src/modbus_port.c`)

| Узел | Проблема исходной реализации | Внесённое исправление |
|---|---|---|
| Чётность `USART1` на STM32 | При `8E1` на STM32 бит чётности входит в ширину слова `M`: настройка `DATAWIDTH_8B` приводила к формату `7E1` и искажению старшего бита байтов | Установлена конфигурация `LL_USART_DATAWIDTH_9B` + `LL_USART_PARITY_EVEN` на скорости `230400` бод |
| Стек мастера и чужие кадры | Высокоуровневый `esp-modbus` и обработка чужих unicast-кадров в `eMBPoll()` на ведомых вносили недетерминированные задержки | Реализован прямой драйвер `rs485_rtu.c` (`rx_full_threshold = 27`, `rx_timeout = 2`); ведомые отбрасывают чужие адресные пакеты непосредственно в `TIM2_IRQHandler` |
| Джиттер периода `poll` | Задержка `vTaskDelayUntil` на тике FreeRTOS `1 кГц` смещала фазу `SNAP` при затягивании отдельного цикла чтения | Запуск циклов `SNAP` переведён на аппаратный периодический таймер `esp_timer` (`ESP_TIMER_ISR`, `10 000 мкс` = `100.000 Гц`) с уведомлением задачи `xTaskNotifyFromISR` |
| Потеря связи `UART0` на `921600` бод | В ESP-IDF v5.x `esp_console_new_repl_uart()` при `baud <= 1 Мбод` принудительно выбирает `UART_SCLK_REF_TICK` (`1 МГц`), что при делителях `17/16` даёт фактическую скорость `~1 000 000` бод (`+8.5%` ошибки) и срыв приёма на ПК | После инициализации REPL выполняется перепривязка `UART0` к `UART_SCLK_DEFAULT` (`APB = 80 МГц`, `922190` бод, погрешность `+0.064%`), а форматирование `DATA` вынесено на Core 1 через `RINGBUF_TYPE_NOSPLIT` (`64 КБ`) |

## 4. Диагностические утилиты (`diagnostics/`)

| Скрипт | Назначение |
|---|---|
| `diagnostics/serial_head_logger.py` | Приём потока `DATA` на `921600` бод, парсинг `ang`, `raw_ang`, `age_us`, `read_us`, `gap_us`, `snap_us`, `poll_us` и запись CSV-логов |
| `diagnostics/residual_plots.py` | Построение временны́х графиков невязки головок после линейного детрендинга (OLS и робастный Huber M-estimator), расчёт RMS / P95 / P2P и гистограмм шага `dt` |
| `diagnostics/head_period_analysis.py` | Разбиение непрерывной записи на полные обороты `[0°, 360°)` от единого нуля при включении, бездырочный детрендинг по целому числу оборотов, анализ полуразности противоположных головок `half_diff` и FFT пространственных гармоник (`H1`, `H2`, `H144`) |

Запуск всех регрессионных тестов описан в разделе 8 [`modbus_rtu.md`](modbus_rtu.md).
