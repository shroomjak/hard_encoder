# hard_encoder
Проект абсолютного энкодера, датчики реализованы на базе STM32 с базовым рабочим ПО при помощи АО "Мостком".

Здесь будет
1. Реализация внешнего интерфейса для получения данных с головки по интерфейсу RS485.
2. Реализация протокола ModBus на основе RS485 для корректной работы нескольких головок, распределения и создания очередности команд, избежания коллизий. Master -- ESP32, slave -- STM32 считывающая головка
3. Проверка самокалибровки и прочих базовых алгоритмов для работы с датчиком угла

## Тесты

```bash
python3 tests/sector_decode_test.py
python3 tests/modbus_snapshot_test.py
python3 tests/encoder_vars_test.py    # extern-мост ↔ Src/main.c
python3 tests/calib_map_test.py       # карта регистров ↔ режим калибровки ESP32 ↔ tools/modbus_calib.py
sh tests/host/run_calib_test.sh       # команды калибровки: защита, откат, окно выгрузки
sh tests/host/run_esp32_modes_test.sh # ESP32 master: рабочий опрос и калибровка, без ESP-IDF
```

`tests/modbus_snapshot_test.py` собирает на хосте с заглушками `Src/modbus_slave.c`
и проверяет контракт FC06 SNAP → FC04 STATUS/DATA: номер последовательности,
метаданные и границу массива `buf_x0`.

Регрессионный тест декодера сектора: извлекает из `Src/main.c` реальные `calc_sector()`,
`bit_err_corr()` и таблицу `bit_tab[]`, собирает их хостовым `gcc` и проверяет полным
перебором все 144 сектора и все 1296 однобитовых ошибок.
См. [`docs/angle_math_and_calibration.md`, §5.3](docs/angle_math_and_calibration.md#53-два-дефекта-декодирования-и-их-исправление).

### 5. Отработка самокалибровки

Раньше происходила по шине SPI — в текущей ревизии канал удалён (см. `docs/main_c_overview.md`, §11).
Команды `0x10…0x14` того канала **восстановлены поверх ModBus RTU**: запуск калибровки конкретной
головки — адресной записью в holding-регистр `CAL_CMD` (FC06), живой статус — блоком входных
регистров 11…30, таблицы выгружаются окном 31…62 (всего 63 входных регистра). Реализация:
`Inc/modbus_calib.h`, `Src/modbus_calib.c`; порядок шагов, регистры и кадры —
[`docs/calibration_modbus.md`](docs/calibration_modbus.md).

Калибровка запускается **режимом «Калибровка головки»** прошивки ESP32 master
(`esp32_master/`, выбор режима в `idf.py menuconfig` → «Encoder master: режим работы»).
Рабочий опрос и калибровка собираются раздельно: на линии в каждый момент работает
один master, и калибровочные команды не уходят во время опроса. Адрес калибруемой
головки — `CONFIG_ENCODER_CALIB_SLAVE` (1…247, вещание запрещено). Порядок команд,
скорости и ожидания те же, что были в `tools/modbus_calib.py`.

Порядок отработки (по §3 документа о калибровке):

1. **Сохранить изначальную таблицу отдельно, вдруг сломаю!** Завершённая калибровка
   перезаписывает `ang_tab` (а следом `offset` и `buf_k`) в EEPROM, и без копии вернуться к
   исходным таблицам будет нечем. Выгрузка по шине в CSV:
   режим калибровки выводит её в монитор автоматически (`CONFIG_ENCODER_CALIB_DUMP`) до
   и после процедуры; сохраните CSV в файлы и сравните:
   `python3 tools/modbus_calib.py diff ang_tab_before.csv ang_tab_after.csv`.
2. Равномерное вращение от привода (не рукой), проверка направления по счётчикам оборотов.
3. `0x14` `buf_k` (10…40 об/мин, 50…70 оборотов) → `0x13` `offset` (10…40 об/мин,
   12…68 оборотов: по 4 на пробу) → `0x11` проход 1 (угол растёт) → `0x12` проход 2
   (угол убывает), оба прохода на 5…20 об/мин → `0x10`. Порядок **обратен нумерации кодов**:
   `ang_tab` нужна готовая точка съёма (строб отсчитывается от `offset`) и выправленные
   границы `s_l1`/`s_l2`, а `min_max` для `0x14`/`0x13` считается по `ang_tab` — поэтому
   `0x14` и `0x13` повторяют вторым кругом после проходов. Между шагами ждать кода
   готовности в `STATE` (`0x80`, `0x60`, `0x20`, `0x40`) и окончания записи в EEPROM
   (бит 0 регистра 30). Прерванную или неудачную калибровку повторяют той же командой.
4. Перезагрузка головки и проверка `ANG_TAB_RDY`/`BUF_K_RDY`/`OFFSET_RDY` — подтверждение, что
   блоки в EEPROM читаются с верной CRC16.
5. **Повторить эксперимент 4 после самокалибровки, сравнить результаты**: `min_max`,
   диагностические графики «до/после», `diff` выгруженных таблиц.
